### Which nearby reviews should a support analyst read together?

A review list sorted by date separates reports that use different words for
a similar problem. This query selects 9,967 sampled low-rating headphone
reviews, projects their 1,024-dimensional BGE-M3 vectors into two dimensions,
and joins the coordinates back to product names and review text.

The cohort is defined inside the algorithm's input subquery. Removing
accessories or changing the sample changes the fitted map. The displayed
snapshot lets a reader inspect the original text at a point before treating
its neighborhood as a useful review group.

<ReviewMap data={reviewMap} />

```sql
SELECT u.id, u.dim_0, u.dim_1, r.product_id,
       p.title AS product_title, EXTRACT(YEAR FROM r.review_time) AS review_year,
       r.rating, r.title, r.embedding_text
FROM cuml_umap(
  input => (SELECT v.id, v.vector
    FROM semantic_reviews_vectors v
    JOIN semantic_reviews_text r ON r.id = v.id
    WHERE r.category_l3 = 'Headphones & Earbuds' AND v.sample_rank < 100000
    ORDER BY v.id),
  n_components => 2, n_neighbors => 30, min_dist => 0.1, random_state => 42) u
JOIN semantic_reviews_text r ON r.id = u.id
JOIN products p ON p.product_id = r.product_id
ORDER BY u.id;
```

UMAP coordinates are a view for exploration. Long distances on this map
have no calibrated business meaning, and compact regions do not establish
product failure categories. Review year is a display color, not an input
feature. Changing the filters in the visualization highlights saved points;
it does not rerun the query.

### Where do the challenge histograms sit in a two-dimensional UMAP view?

This query fits UMAP to all 3,225 Win32 challenge files using their 512-element
normalized histograms, with `n_neighbors = 30` and `random_state = 42`. The SQL
joins labels, weeks, SHA-256 values, and family names after the projection.
These fields support later inspection; they are not UMAP input columns.

The saved scatter includes all query rows and lets you select a captured
projection. Its HDBSCAN filter uses the separate PCA-16 cluster assignments.
Changing a projection or filter only selects saved output rows. It does not
rerun UMAP or HDBSCAN.

<EmberMap data={emberMap} initialProjection="umap" />

```sql
SELECT u.id,
       u.dim_0,
       u.dim_1,
       v.label,
       m.week_id,
       m.sha256,
       m.family
FROM cuml_umap(
    input => (
        SELECT r.id, r.histogram AS vector
        FROM ember_research_vectors_challenge r
        JOIN ember_metadata_challenge m ON m.id = r.id
        WHERE r.split = 'challenge' AND m.file_type = 'Win32'
        ORDER BY r.id
    ),
    n_components => 2,
    n_neighbors => 30,
    random_state => 42
) u
JOIN ember_research_vectors_challenge v ON v.id = u.id AND v.split = 'challenge'
JOIN ember_metadata_challenge m ON m.id = v.id
ORDER BY u.row_ordinal;
```
