# cuML SQL API

Algeon exposes NVIDIA RAPIDS [cuML](https://github.com/rapidsai/cuml) as
GPU UDTFs (user-defined table functions) in DataFusion SQL sessions. A UDTF
either fits a model inside the statement (TSVD, HDBSCAN, UMAP, logistic
regression, random forests) or scores rows with a pretrained XGBoost,
LightGBM or Treelite forest (`cuml_forest_predict`). Each result carries a
`row_ordinal` and the `id` of the row it describes.

## UDTFs

Start with [cuML UDTFs](./udtfs/index.mdx) to choose a decomposition,
clustering, embedding, classification, regression or pretrained-forest
UDTF and read its generated option and output schema.

## Input and call shape

Each relation argument (`input`, `training`, or `predict`) is a parenthesized `SELECT` subquery. Ordinary session
tables and views can supply the projected rows. A bare table identifier is not
an execution argument. [ML Inputs](./ml-inputs.mdx) specifies the canonical
`id`, feature layouts, element types, and checks at planning and execution.

For metadata validation, `gpu_validate_call` resolves a registered table or
view and inspects its schema without evaluating rows.

## Execution and lifetime

Embedded sessions install this SQL family with `try_with_cuml_sql()`, or
with `try_with_cuml_sql_config(CumlSqlConfig)` to configure the models root
that `cuml_forest_predict` reads. The Flight SQL server installs
it for each session by default. GPU execution requires a binary built with
the `cuml` Cargo feature and an installed `AlgeonGpuBackend`; otherwise
catalog entries remain discoverable with `available=false` and
`required_feature_disabled`. The [DataFusion session
guide](../integration/datafusion-session.mdx) describes backend,
execution-mode, and `CumlSqlConfig` setup.

The six fitting UDTFs evaluate their input within one statement.
Models and transforms are released after that call; there is no model cache,
cross-statement reuse, or serialization, and no inference for neural
networks trained in PyTorch. `cuml_forest_predict` instead reads
and binds a model file from a server-configured models root; without one
configured, it is listed but unavailable with `model_root_unconfigured`. See
[Configuration](../integration/configuration.mdx#models-and-forest-inference)
for the `[models]` TOML table. Allocations run within the admitted query
memory cap. Requests exceeding that cap produce a typed allocation error.

The [GPU table functions design](../design/gpu-table-functions.mdx#cuvs-and-cuml-layouts-and-result-ownership)
connects feature-matrix and model lifetimes to output ownership, native SQL
consumers and the shared query memory cap.
