# Logistic Regression

UDTF: `cuml_logistic_regression`

Official cuML reference: [Python API](https://docs.nvidia.com/cuml/latest/api/generated/cuml.linear_model.LogisticRegression/)

Fit a query-local cuML logistic or softmax classifier and score independent rows.

## Quickstart

Register the relations referenced by the parenthesized `SELECT` clauses below. For metadata validation, the descriptor names `training_vectors` and `predict_vectors`.

```sql
SELECT id, prediction, probability
FROM cuml_logistic_regression(
  training => (SELECT id, d0, label FROM train),
  predict => (SELECT id, d0 FROM test)
)
ORDER BY row_ordinal;
```

### Vector binding shapes

Each relation subquery projects an `id` and either Float32 feature columns in dimension order or one `vector` list column of Float32 values. For classification, `training` also projects Int32 `label`; regression requires finite Float32 `label`. The `predict` relation omits it. Nullable field types are accepted; a null ID, feature value, list row, list element, or label fails the query.

The list-column shape excludes other feature columns. See [ML Inputs](../ml-inputs.mdx) for the allowed list containers and runtime checks.

## Limits

- Validation resolves named tables or views and reads schemas only; it does not execute relation scans or GPU work.
- Execution relation arguments require parenthesized subqueries; dry-run validation accepts registered named relations only.
- Training labels must be Int32 contiguous classes 0..C-1 and must not be null; predict must omit label and match the feature dimension.
- Binary labels use logistic loss; three or more classes use softmax. Reaching max_iter is not an error.
- probability covers only the predicted class; per-class probabilities are not returned. Class weights are not exposed, so threshold probability to trade precision for recall.
- The model is query-local. An empty predict relation returns an empty result without a native call.
- Coefficients and scores can differ slightly between runs, because the loss reduction accumulates with floating-point atomics; there is no seed option.

To dry-run validate relation metadata, column types, and options without execution, see [`gpu_validate_call`](../../reference/gpu-udtf-catalog.mdx).
