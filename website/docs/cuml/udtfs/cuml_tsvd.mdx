# TSVD

UDTF: `cuml_tsvd`

Official cuML reference: [Python API](https://docs.nvidia.com/cuml/latest/api/generated/cuml.decomposition.TruncatedSVD/)

cuML truncated SVD fits and transforms dense feature rows.

## Quickstart

Register the relations referenced by the parenthesized `SELECT` clauses below. For metadata validation, the descriptor names `input_vectors`.

```sql
SELECT id, pc_0, pc_1
FROM cuml_tsvd(
  input => (SELECT id, d0, d1 FROM t),
  n_components => 2
)
ORDER BY row_ordinal;
```

### Vector binding shapes

Each relation subquery projects an `id` and either feature columns in dimension order or one list column, with the element types listed under Vector element types. Nullable field types are accepted. A null ID, feature value, list row, or list element fails the query.

The list-column shape excludes other feature columns. See [ML Inputs](../ml-inputs.mdx) for the allowed list containers and runtime checks.

## Limits

- Empty input returns an empty result without a native call. Nonempty input requires at least two evaluated rows and two feature dimensions. n_components cannot exceed dimension; known dimensions are checked during planning, otherwise execution reports a structured error.
- Float64 features, as wide columns or list elements, are narrowed to Float32 on the device before training or inference. Each value rounds to the nearest Float32, which keeps about seven significant digits; a value beyond the Float32 range becomes infinite and fails the query.
- Component sign is not semantic; this operation returns transformed rows only, not components, explained variance, or mean.
- TSVD allocates a temporary rows * n_components score matrix inside the query device cap.
