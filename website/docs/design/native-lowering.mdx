# Native Lowering & Final Plans

Native lowering converts a completed DataFusion `ExecutionPlan` tree into the
query engine's `QueryPlan` IR. When the converted plan wins final selection,
it replaces the original plan with a wrapper node that executes the
`QueryPlan` on the native engine instead.

It runs after DataFusion physical planning has finished, so it translates
decisions DataFusion already made (aggregate mode, join shape, scan pushdown,
partitioning, output order) rather than replanning them. The two plan models
differ in one important way: `ExecutionPlan` is an open trait, so DataFusion
can produce any operator shape, while `QueryPlan` is a closed,
DataFusion-free set of nodes owned by the engine. Lowering handles only the
shapes it can map exactly and declines the rest with a structured reason
(step 1).

To DataFusion, all of this is ordinary machinery: three `PhysicalOptimizerRule`s
and, when selection succeeds, an `ExecutionPlan` wrapper node in the completed
plan.

The planning path is:

~~~text
DataFusion ExecutionPlan
  -> normalize and validate the completed physical shape
  -> lower one supported candidate to QueryPlan
  -> optimize IR, apply cost selection, and check execution capability
  -> AlgeonNativeExec or AlgeonNativeComposedExec
  -> capability evidence and, when needed, a QueryAdmissionTicket
~~~

Runtime admission and device-memory accounting begin later. See
[Admission & Memory Governance](./admission.mdx).

## Session wiring

The backend's `AlgeonGpuExecutionMode` controls relational selection.
`NativePreferred` (the default) enables it and permits DataFusion CPU execution;
`NativeRequired` enables it and rejects a completed plan containing DataFusion
CPU operators. `FunctionsOnly` disables relational rewrites while retaining
explicit cuGraph/cuVS execution and the same backend admission authority. See
[Choose an execution mode](../integration/datafusion-session.mdx#choose-an-execution-mode)
for configuration and CPU/GPU composition limits.

`with_algeon_native` installs two physical optimizer rules around DataFusion's
own rules:

| Rule | Position | Responsibility |
| --- | --- | --- |
| `algeon_datafusion_native_count_only` | Before `aggregate_statistics` | Capture safe zero-column count shapes before DataFusion replaces them with statistics. |
| `algeon_datafusion_native` | After the other physical optimizer rules, immediately before `SanityCheckPlan` | Make the final native selection. Under `NativeRequired`, its last step rejects the completed plan when it contains DataFusion CPU operators. This public name is also the deduplication key. |

Rules added to the session builder after `with_algeon_native` run after
`SanityCheckPlan`, so the `NativeRequired` check does not see their output.

The entry points are `crates/algeon-datafusion/src/session.rs` for rule ordering and
`AlgeonNativePhysicalOptimizerRule::optimize` in `crates/algeon-datafusion/src/planner/native.rs` for the
rewrite. The rule is idempotent: an admission wrapper, `AlgeonNativeExec`,
`AlgeonNativeComposedExec`, or a
[certified mixed plan](#selection-fallback-and-mixed-execution) is not lowered
again.

## Lowering pipeline

### 1. Recognize a physical candidate

`crates/algeon-datafusion/src/native/normalize.rs` removes only known transparent wrappers and builds a
`NormalizedNativePlan` for an exact supported shape. Operator, expression,
type, source, and ordering checks stay in `crates/algeon-datafusion/src/native/validate.rs`,
`crates/algeon-datafusion/src/native/expression_contract/`, and the source-specific lowering code.

Normalization is deliberately narrower than DataFusion's plan model. A miss
returns a stable `CapabilityReason`; it does not guess at an equivalent plan.

### 2. Build engine-owned IR

`crates/algeon-datafusion/src/native/lowering/` recursively translates the normalized tree with
`QueryPlanBuilder`. The result is an append-only DAG of engine `PlanNode`s with
an explicit `ResultSink`. The host sink preserves the DataFusion output schema,
including schema metadata.

Declared ordering is part of the replacement contract. Lowering must prove the
native plan reproduces it or append a supported native sort. Otherwise the
candidate remains on DataFusion with `NativeOrderedOutputUnsupported`.

### 3. Select an executable native plan

`replace_lowered_root_or_keep_plan` in `crates/algeon-datafusion/src/planner/native/attempt.rs` accepts
only one lowered plan with one selected candidate. It then:

1. runs the engine-owned native optimizer;
2. rechecks declared output ordering;
3. applies the engine-owned native cost decision; and
4. builds capability diagnostics and rejects a plan whose kernel, type, or
   semantic requirements are unsupported before creating a wrapper. Memory
   sizing is not part of this check; the query allocator enforces the grant at
   run time.

Every non-selection returns the original executable DataFusion plan. A
native-capable plan declined by cost is distinct from an unsupported plan.

### 4. Choose the DataFusion wrapper

The selected candidate is wrapped in one of two `ExecutionPlan` nodes:

- `AlgeonNativeExec` for plans with ordinary sources.
- `AlgeonNativeComposedExec` for plans that read named GPU-resident sources.
  Its children are the explicit GPU producers, and the wrapper checks that the
  required and provided input names match exactly. This is GPU-to-GPU
  composition, not arbitrary relational fragment extraction.

The planner also attaches admission evidence. Each selected fragment records
the device capabilities and exact plan scope needed for execution. When the
session config is set up for planner-side admission (an admission source and
no `QueryServiceHandle`), the fragment evidence is combined into one
`QueryAdmissionTicket` bound to the plan. Device and grant acquisition wait
until execution. Configs that already hold a `QueryServiceHandle` use that
handle's context. A cuGraph root binds its evidence after lakehouse footer
metadata has resolved so the admitted scope matches the executable plan.

## Selection, fallback, and mixed execution

`PlanningReport` is the public planning evidence. Assert its structured
outcomes rather than formatted plan text:

| Outcome | Meaning |
| --- | --- |
| `Selected` | The candidate became native IR and passed final selection. |
| `NotSupported` | A `CapabilityReason` identifies the unsupported semantic, source, ordering, or execution contract. |
| `NotSelectedByCost` | The candidate is supported, but the native cost decision retained DataFusion and records its evidence. |

The rule keeps no per-query state. Each planning call records its
diagnostics on its own invocation: `plan_with_native_diagnostics` plans a
logical plan and returns that call's diagnostics, `AlgeonAttempt::planning_diagnostics`
returns the latest planning pass of an attempt, and
`AlgeonNativePhysicalOptimizerRule::optimize_with_diagnostics` applies the rule
to one physical plan. The bundle pairs the report with native optimizer,
source, and capability evidence of that one call.

When enabled, relational selection is whole-candidate by default. Explicit GPU
UDTFs can separately compose with DataFusion CPU operators, including in
`FunctionsOnly` mode. The narrow relational rewrite exception lives in
`crates/algeon-datafusion/src/planner/native/mixed.rs`: when whole-plan lowering misses on
an unsupported expression, Algeon may certify a final CPU `ILIKE` filter over a
single local-Parquet source and replace only that source with a native
host-output leaf. The certificate checks the exact shape, source, schema, and
physical properties, then rebuilds the CPU filter from the new child. Do not
generalize this into a subtree extractor; a new mixed boundary needs its own
complete property and ownership proof.

## Native execution boundary

`AlgeonNativeExec` and `AlgeonNativeComposedExec` are ordinary DataFusion
`ExecutionPlan`s with one bounded output partition. At execution they acquire
the admitted native context, run the engine's observed execution entry point,
and expose Arrow `RecordBatch`es to the caller. The composed form first turns
its producer results into the `GpuResidentInputMap` consumed by the native
plan, avoiding an intermediate host materialization.

The runtime observation snapshot is the source for engine `QueryMetrics`,
DataFusion metrics, and native report projections. Once native execution has
started, a failure is returned as a structured error; the query is not replayed
through the retained CPU plan.

Inside the wrapper, the engine may execute independent work on multiple
lanes of the one admitted attempt: task claims, aggregate source chunks,
and fused top-k sort candidates. The wrapper boundary is unchanged by this:
one output partition, declared ordering preserved, `Final` emission. A
global top-k merges per-chunk candidates with the same comparator and
applies the offset once at the end; concatenated sorted chunks are never
presented as a global sort. GPU-resident sinks adopt lane-produced frames
onto the root runtime before the lane leases release.

## Baseline preservation and final-plan requirements

`NotSupported` and `NotSelectedByCost` are planning outcomes, not errors. The
original DataFusion plan remains executable unless the caller configured a
completed-plan requirement.

`classify_final_plan` walks the exact result and reports `DataFusion`, `Native`,
or `Mixed`. `FinalPlanRequirement::NoDataFusionCpu` rejects a completed plan
that would execute DataFusion CPU operators. A feature-disabled cuGraph
terminal is exempt because it executes neither CPU nor GPU work. An
unsatisfied requirement returns `FinalPlanRequirementUnsatisfied`; `Rejected`
is the terminal planning outcome, not another physical node.

## Extending native lowering

Keep changes at the owner of the missing contract:

| Change | Extend |
| --- | --- |
| Recognize another DataFusion physical shape | `crates/algeon-datafusion/src/native/normalize.rs`, `crates/algeon-datafusion/src/native/validate.rs`, and the existing module in `crates/algeon-datafusion/src/native/lowering/` |
| Add or change native IR semantics | `crates/algeon-query-planning/src/plan/`, `crates/algeon-query-planning/src/optimizer/`, and `crates/algeon-query-planning/src/capability/`; execution changes remain in `crates/algeon-query-engine/src/exec/` |
| Add an explicit GPU producer or graph island | The existing `GpuResidentProducer` or `GraphExecutionPlan` boundary in `crates/algeon-datafusion/src/native_exec/`, then compose through the current wrappers |
| Add a missing cuDF or cuGraph primitive | `components/cudf` or `components/cugraph`; do not emulate it in the DataFusion adapter |
| Add a missing cuVS primitive | `components/cuvs`; preserve runtime binding, tensor ownership, and completion contracts |
| Change selection evidence | `crates/algeon-datafusion/src/report.rs`, `crates/algeon-datafusion/src/capability.rs`, and the existing public report projections and contract tests |

Extend `tests/native_planning/lowering.rs` for lowering and report behavior,
`tests/native_exec_tests.rs` for selection, fallback, mixed, and wrapper
contracts, and the engine's `native_contract_tests` for DataFusion-independent
behavior. A useful focused loop is:

~~~bash
cargo nextest run -p algeon-datafusion --all-features --test native_planning_tests
cargo nextest run -p query-engine --all-features --test native_contract_tests
~~~
