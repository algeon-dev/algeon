# Cache Design and Use

P2 keeps the bounded controller's per-device allocation domain query-owned.
Cross-query GPU retention is therefore off: an immutable query grant is the
complete hard cap for that attempt, and no retained source frame or graph can
consume capacity from a later attempt.

| Layer | P2 status | Scope and capacity |
| --- | --- | --- |
| Lakehouse byte cache | Available | Complete remote Parquet objects on local storage. `NEXUS_LAKEHOUSE_CACHE_MAX_BYTES` is a best-effort retained-byte target. |
| Decoded source cache | Not part of P2 | No cuDF source frames are retained between bounded queries. |
| Resident graph cache | Not part of P2 | No cuGraph graphs are parked between bounded queries. |

Query-local DAG results and repeated hash-join builds may still be memoized for
one execution. They are released with that query and are not a cross-query
device cache.

## Recommended server setup

The lakehouse byte cache is filesystem storage, not a GPU allocation. It can be
enabled independently of the bounded controller:

```bash
NEXUS_LAKEHOUSE_CACHE_ROOT=/var/cache/datafusion-nexus/lakehouse \
NEXUS_LAKEHOUSE_CACHE_POLICY=read_through \
NEXUS_LAKEHOUSE_CACHE_MAX_BYTES=536870912000 \
flock /tmp/cudf-gpu.lock bash scripts/dev/run_server.sh
```

P2 exposes no GPU cache capacity setting. Its immutable-grant contract covers
only query-owned allocations; a later P5 cache needs one separately accounted
owner before it can retain device memory across attempts. The old
query-memory-domain multiplier is not a P2 setting.

## Lakehouse byte cache

The byte cache is used by remote table-format Parquet source resolution when
`NEXUS_LAKEHOUSE_CACHE_ROOT` is set. A hit must be a complete object matching
the planned metadata; partial or stale entries are not served.

`NEXUS_LAKEHOUSE_CACHE_POLICY` controls misses:

- `disabled`: read the selected remote path and do not fill a miss;
- `read_through`: serve the foreground query remotely and enqueue a bounded
  background complete-object fill;
- `fill_before_read`: fetch and publish the complete local file before cuDF
  opens it.

`NEXUS_LAKEHOUSE_CACHE_READ=enabled` is the default. Set it to `bypass` or
`disabled` to ignore hits for an isolated benchmark while retaining the files.
Cache paths are scoped by credential-free storage-domain identity, content
identity, and location fingerprint. Publication is completion-aware, active
reads are pinned against eviction, and retention cleanup protects the file
being filled or read.

## Disabled GPU cache migration code

The decoded-source and resident-graph implementations are isolated engine
substrate for later work, not a supported P2 controller profile. They have no
production route and must not affect device placement, reduce an attempt's
allocation-domain cap, or retain device allocations after query cleanup.

P2 has no public source- or graph-cache report rows, metrics, or admission
snapshots. Do not add a compatibility projection or a second cache state store
before the P5 owner exists.

## Verify the active behavior

Lakehouse source diagnostics report `lakehouse_cache_status`, read mode, and
fill mode. Background fills also emit structured completion/failure events.
P2 admission diagnostics intentionally contain no cross-query GPU-cache
profile, retained-byte, entry, or activity fields.
