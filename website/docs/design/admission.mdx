# Bounded GPU Admission

Nexus has one runtime admission contract for native GPU work. It is shared by
embedded SessionContext users and the Flight SQL server; server environment
variables lower onto the same engine policy and do not create another
controller.

Plan support is decided separately by native lowering. Runtime admission begins
only when a supported plan first executes.

## Contract

- Each configured CUDA device has one process-owned DeviceLedger.
- An accepted attempt receives an immutable MemoryGrant. The grant is both its
  hard memory cap and its allocation-domain ceiling for the lifetime of that
  attempt.
- A device profile fixes the root worker, auxiliary lane, stream, and active
  attempt bounds before work starts. It is not resized by load.
- The usable global active-attempt capacity is the checked sum of the
  per-device active limits. There is no fixed global GPU-concurrency product
  knob.
- Capability-first checks reject unsupported or impossible work locally with a
  structured reason. Queueing cannot make an impossible request admissible.
- There is no tenant identity, priority tier, QoS weighting, grant band,
  placement-policy selector, slot-guarantee mode, or strict/adaptive product
  mode in the admission path.

The controller may rank compatible devices, but the resulting placement is an
engine decision from fixed device facts and live ledger state. It is not a
caller-selected policy.

## Attempt lifecycle

1. Native lowering attaches one lazy attempt admission to the execution round.
   Planning and EXPLAIN do not consume a device slot.
2. At execution, the service evaluates capability requirements and ranks
   compatible devices.
3. The admission transaction reserves an immutable grant, device lane, stream,
   allocation domain, and worker resources. A failed step rolls the preceding
   reservations back in reverse order.
4. Execution uses that one grant for its complete attempt domain. A grant never
   grows, shrinks, borrows, or is revoked while live.
5. Cleanup seals runtime observation and commits terminal disposition and
   health before the ledger releases the attempt's capacity. A replacement
   cannot observe reusable capacity before report completion.
6. A cleanup failure or unknown CUDA-fault isolation latches the backend
   unhealthy and prevents reuse rather than returning capacity.

This ordering gives reports, DataFusion metrics, and TSV output one source of
truth: the runtime observation snapshot.

## Queue and fairness

The queue is bounded by maximum waiters, maximum wait time, and a finite
compatible-device overtake budget. It is a liveness mechanism, not a tenant
scheduler:

- impossible requirements reject immediately;
- the oldest runnable compatible request wins once its overtake budget is
  exhausted;
- a request can be bypassed only while a compatible device can make progress;
- service close, cancellation, deadline expiry, or backend-unhealthy state
  completes every affected waiter with a structured outcome.

## Device profiles and capacity

A backend resolves a DeviceResourceProfile for each selected device. The
profile declares active-attempt, root-worker, auxiliary-lane, and stream
bounds. Its attempt floor is configured explicitly or derived per device as
managed_bytes / max(8, active_attempts).

For an empty device with managed capacity M, live granted bytes L, floor F, and
E empty active-attempt slots, a candidate grant is bounded by:

~~~text
max_new = M - L - F * E
~~~

The transaction rejects any non-positive or capability-insufficient candidate.
Heterogeneous devices keep their own profiles; no average or global split is
substituted for their individual limits.

## Server configuration lowering

The Flight SQL server accepts resource-only inputs:

| Env | TOML | Meaning |
| --- | --- | --- |
| — | admission.device_profiles | One explicit ordinal device profile per selected GPU. It owns only resource inputs: memory limit/reserve, attempt floor, active-attempt cap, source-work bound, and installation bounds. |
| NEXUS_SERVER_ADMISSION_MAX_QUEUED_ATTEMPTS | admission.max_queued_attempts | Queue capacity; default 64. |
| NEXUS_SERVER_ADMISSION_MAX_QUEUE_WAIT_MS | admission.max_queue_wait_ms | Queue deadline; default 30000. |
| NEXUS_SERVER_ADMISSION_MAX_OVERTAKES_PER_WAITER | admission.max_overtakes_per_waiter | Finite compatible-device bypass budget; default 4. |
| NEXUS_SERVER_GPU_DEVICES | — | Comma-separated CUDA device ordinals; default 0. |

GPU-memory ownership and exact capability restrictions are supplied by the
embedding process when it builds the backend; TOML does not invent either.
The scalar admission inputs, placement selector, slot guarantee, tenant policy,
strict/adaptive controller modes, and global device-budget fraction are removed.
They are not compatibility projections and cannot be reconstructed from
diagnostics.

## Observability and shutdown

Each native execution round records an admission sequence, wait time, device
ordinal, grant bytes, reservations, and terminal disposition in the runtime
observation snapshot. The same snapshot projects to native TSV reports,
DataFusion metrics, JSONL artifacts, and QueryMetrics.

Close is coordinated in dependency order. Backend cleanup drains admitted
attempts before execution pools; execution pools finish before stream cleanup;
observation completion consumes the final tail. CUDA-capable workers register
for process exit and are synchronously joined before CUDA runtime teardown, so
a detached worker cannot race libcudart finalization.

## Boundaries

- DataFusion MemoryPool governs host allocations. GPU grants and allocation
  domains stay in the device ledger.
- The controller does not provide authentication, authorization, application
  rate limiting, idempotency, result retention, or tenant policy.
- Native caches remain disabled in the Phase 2 baseline. Future cache work
  needs allocator-backed ownership rather than a hidden cross-query grant.
- cuGraph and cuVS stages use the same per-attempt capability and reservation
  contract. A missing preflight remains a local structured rejection, never a
  fallback admission mode.
