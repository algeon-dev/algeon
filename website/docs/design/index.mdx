# Design

DataFusion Nexus is a **DataFusion-native integration layer**. DataFusion keeps
SQL parsing, logical planning, physical planning, catalogs, DataFrame APIs, and
CPU execution. Nexus adds opt-in cuDF execution, SQL-visible cuGraph algorithms,
Iceberg/lakehouse source handling, and structured diagnostics around that
DataFusion session.

- **For users:** the GPU path is an implementation detail behind ordinary DataFusion or Flight SQL APIs.
- **For developers:** every native decision must be local, reportable, and backed by an adapter or engine contract.
- **Non-goals:** Nexus is not a separate SQL engine, does not accept Substrait plans, and does not implement single-query cross-GPU execution.

## The design contract

- **DataFusion stays in charge:** SQL, catalogs, physical planning, and
  CPU-readable fallback remain stock DataFusion. GPU-only table-format leaves
  fail planning if native lowering cannot consume them.
- **The adapter translates:** `src/` recognizes DataFusion physical shapes,
  lowers supported candidates into `QueryPlan`, and exposes reports.
- **The engine owns native execution:** `crates/nexus-query-engine` has no
  DataFusion dependency. It owns the IR, capability analysis, execution-time
  context, and executor.
- **RAPIDS capability belongs below:** Missing GPU APIs, memory hooks, device
  interop, or graph contracts belong in `cudf-rs` / `cugraph-rs`, not adapter
  workarounds.

## Integration surfaces

| Surface | Use it when | Primary owner |
| --- | --- | --- |
| Embedded DataFusion backend | You already own the service API, auth, tenancy, and domain model. Install Nexus on a caller-owned `SessionStateBuilder`. | `src/session.rs` |
| Flight SQL service | You want a ready remote endpoint for notebooks, BI tools, agents, and non-Rust clients. | `src/server/` |
| cuGraph SQL | You want graph algorithms as relations that can be joined, filtered, validated, and described from SQL. | `src/graph_sql/` |
| Iceberg/lakehouse sources | You need Iceberg catalog tables to lower into native table-format scan facts while workspace views stay mutable. | `src/table_format/` |
| Reports and errors | You need stable evidence for admission, fallback, runtime, graph validation, source access, and failures. | `src/report.rs`, `src/native_report/`, `src/error.rs` |

The preferred embedded entry point is a process-scoped `NexusGpuBackend`. It
installs the native optimizer and gives every installed session the same
QueryService admission owner and device-memory governor. The cuGraph line is
available only when the crate is built with `--features cugraph`; omit it for a
pure relational session.

```rust
let backend = NexusGpuBackend::builder()
    .fallback_policy(GpuFallbackPolicy::GpuPreferred)
    .build()?;
let cugraph = CugraphSqlConfig::default()
    .with_native_execution_config(backend.optimizer_config().native_execution_config().clone());

let state = backend
    .install_on(SessionStateBuilder::new().with_default_features())?
    .with_cugraph_sql(cugraph)
    .build();
```

### Fallback policy

`GpuPreferred` leaves rejected CPU-readable candidates on DataFusion's CPU
path; `GpuOnly` turns the first native rejection into a planning error. The
full boundary — including how GPU-only table-format scan leaves fail planning
instead of falling back — is described in
[Fallback policy boundary](./native-lowering.mdx#fallback-policy-boundary).

### Feature gates

| Feature | Adds |
| --- | --- |
| `cugraph` | cuGraph SQL algorithms and engine graph execution support. |
| `server-cugraph` | Flight SQL server plus cuGraph SQL. |
| `iceberg` | Iceberg / Glue / REST / S3 source integration through native table-format scans. |

### Why two crates

The split is structural, not cosmetic. `nexus-query-engine` deliberately
consumes a closed, owned `QueryPlan` instead of DataFusion's open
`ExecutionPlan` trait.

- DataFusion's physical trait changes with DataFusion releases; the engine's IR
  remains a stable native execution contract.
- Physical planning has already decided aggregate modes, partitioning,
  projection pushdown, join shape, and scan facts. Native lowering needs those
  decisions.
- Engine tests can pin capability analysis, strict/adaptive separation,
  reservation behavior, and executor semantics without DataFusion in scope.
- Non-DataFusion frontends can construct the same native IR directly.

The current `PlanNode` variants are `Source`, `Filter`, `Projection`,
`Aggregate`, `Window`, `Sort`, `Limit`, `Join`, `Union`, `EdgeNormalize`, and
`GraphAlgorithm`.

### Placement rules

| Change | Correct home | Contract to update |
| --- | --- | --- |
| Support a new DataFusion physical shape | `src/native/normalize.rs`, `src/native/lowering/`, `src/native/validate*` | Planning reports and fallback reasons |
| Add native IR or executor behavior | `crates/nexus-query-engine/src/plan`, `expr`, `source`, `exec` | Engine contract tests and metrics |
| Admit a bounded compiled shape | `crates/nexus-query-engine/src/capability`, `pipeline`, `exec/bounded` | Strict/adaptive diagnostics; no family-name shortcuts |
| Improve GPU memory, streams, source readers, or graph interop | `cudf`, `cugraph`, `rapids-interop` crates | Binding crate API and FFI error mapping |
| Change public evidence | `src/native_report/`, `src/native_exec/metrics.rs`, `src/error.rs` | Public surface schema/version constants |

## cuGraph SQL path

With `--features cugraph`, graph algorithms are SQL table functions. The SQL
surface has 24 algorithm functions from `CUGRAPH_OPERATION_REGISTRY`, plus
`cugraph_list_algorithms`, `cugraph_describe_algorithm`, and
`cugraph_validate_call` for discovery and dry-run validation.

```sql
SELECT * FROM cugraph_pagerank('edges', 'src', 'dst')
ORDER BY value DESC;
```

For callers, the recommended workflow is:

1. `cugraph_list_algorithms()` to discover enabled functions.
2. `cugraph_describe_algorithm('<fn>', 'verbose')` to inspect signatures,
   options, schemas, and limitations.
3. `cugraph_validate_call('<fn>', '<table>', '<call_json>')` to check a concrete
   call without scanning edges or launching CUDA.
4. Execute the `cugraph_*` function once validation returns `valid = true`.

The detailed function reference lives in [cuGraph SQL API](../cugraph/overview.mdx).

## Lakehouse and workspace boundary

Iceberg catalogs are source catalogs. They are not the mutable workspace. Nexus
keeps these concerns separate:

- Iceberg and Glue/REST metadata resolve to adapter-owned table providers and
  format-neutral scan facts.
- Interactive DDL such as `CREATE VIEW` belongs in a mutable DataFusion
  workspace, including graph edge views built over source tables.
- The Flight SQL server can expose a workspace overlay so users get short names
  without teaching a read-only Iceberg catalog to accept views.

Iceberg/Glue/S3 is feature-gated behind `--features iceberg`; tests must not
require a real AWS account.

## Developer checklist

Use this page as the routing table before changing behavior:

| If you are changing... | Inspect first | Keep stable |
| --- | --- | --- |
| Native rewrite coverage | `src/native/normalize.rs`, `src/native/lowering/`, `src/native/validate*` | `PlanningReport`, `FallbackReason`, rule names |
| Native execution semantics | `crates/nexus-query-engine/src/exec/`, `capability/`, `pipeline/` | Strict/adaptive separation and reservation evidence |
| cuGraph SQL behavior | `src/graph_sql/types.rs`, `parser.rs`, `metadata/`, `exec.rs`, engine `exec/graph_algorithm/` | Metadata schema versions and validation output |
| Iceberg/source behavior | `src/table_format/`, `src/table_format/iceberg/`, server workspace configuration | Source diagnostics and credential-safe error facts |
| Public diagnostics | `src/native_report/schema.rs`, `src/native_exec/metrics.rs`, `src/error.rs` | TSV headers, schema versions, metric names, `ErrorCode`s |
