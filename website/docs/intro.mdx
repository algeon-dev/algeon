# Welcome to Algeon

**Algeon** brings specialized GPU algorithms into composable SQL workflows
over open data. [Apache DataFusion](https://datafusion.apache.org/) is the
first integration: supported SQL operations run on
[cuDF](https://docs.rapids.ai/api/cudf/stable/), while
[cuGraph](https://docs.nvidia.com/cugraph/latest/) and
[cuVS](https://docs.nvidia.com/cuvs/home) and
[cuML](https://docs.nvidia.com/cuml/latest/) algorithms appear as SQL UDTFs
(user-defined table functions) that compose with joins, filters, and
aggregations. You can embed the DataFusion adapter in a Rust application or
connect through Arrow Flight SQL.

DuckDB is the next narrow adapter direction and Spark is a longer-term
direction; neither is supported today.

GPU execution is opt-in per query: plans, or parts of plans, that Algeon does
not select for GPU execution stay on the normal DataFusion CPU path with the
same results. Once GPU execution starts, a failure is returned as a structured
error and is not re-run on CPU. Selection normally replaces a
[whole candidate](./design/native-lowering.mdx#selection-fallback-and-mixed-execution)
(with one certified
[mixed exception](./reference/glossary.md#planning-and-lowering)), and each
run executes inside a fixed GPU memory
[grant](./design/admission.mdx#device-profiles-and-grants).

- **Build, then run a first query.** Follow
  [Build & Test](./build/overview.md), then either embed Algeon in a
  [DataFusion session](./integration/datafusion-session.mdx) or start the
  [Flight SQL server](./integration/flight-sql-server.mdx) and connect with an
  ADBC client.
- **See what SQL is supported.** Relational coverage is mapped in

## Features

- **GPU execution behind DataFusion APIs.** Supported physical plans run on
  cuDF without changing your SQL, DataFrame code, or result format. You can
  require that a plan contain no CPU execution and have it rejected otherwise.
- **Graph, vector, and ML algorithms in SQL.** `cugraph_*` UDTFs run
  PageRank, BFS, Louvain, ForceAtlas2, and other algorithms over relations;
  `cuvs_*` UDTFs run exact kNN, KMeans, and PCA over vector columns. Both
  return ordinary rows. Six `cuml_*` UDTFs fit query-local models for
  dimensionality reduction, clustering, embedding, classification, and regression.
- **Function discovery and validation.** The
  [GPU UDTF catalog](./guides/gpu-function-discovery.mdx) lists the
  functions installed in a session, describes each contract, validates a call
  before execution, and reports whether each function is executable.
- **Parquet sources.** GPU scans read local and S3-compatible Parquet. Remote
  sources are read-only, with an optional local workspace for views and scratch
  tables. Iceberg is not supported in this release; see
  [Iceberg support](./integration/overview.mdx#iceberg-support).
- **Answers before and after execution.**
  [`algeon_explain_coverage`](./integration/gpu-coverage-validation.mdx)
  (or `EXPLAIN GPU` over Flight SQL) tells you which parts of a query will run
  on the GPU and why the rest will not; errors carry stable machine-readable
  codes.

## Current limitations

- **A subset of SQL runs on the GPU.** Unsupported operators, expressions, and
  Arrow types stay on the DataFusion path. See
  [Native SQL Support](./reference/native-sql-support.mdx) and
  [Data Type Support](./reference/data-type-support.md).
- **One GPU per query.** Independent queries can be spread across configured
  GPUs, but a single query never spans devices.
- **No spilling.** Each query runs inside the GPU memory cap it is granted;
  exceeding it returns an allocation error instead of spilling to host memory
  or disk in the style of [cuCascade](https://github.com/NVIDIA/cuCascade).
- **Algorithm coverage is fixed.** The documented cuGraph, cuVS, and cuML
  functions are available when their Cargo features are enabled. Unsupported
  types and options return structured errors. The
  [cuOpt SQL API](./cuopt/overview.mdx) remains work in progress.
- **GPU file scans are Parquet-only.** Iceberg position deletes are supported
  when their scan is otherwise supported; equality deletes, delete vectors,
  non-Parquet files, and other source types stay on the DataFusion path.
