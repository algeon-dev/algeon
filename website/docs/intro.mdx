## Compose algorithms {/* #from-a-question-to-a-working-set */}

A statement passes a subquery to a GPU UDTF (user-defined table function)
and gets rows back. SQL groups those rows, joins them to names or labels, or
passes them to another UDTF. The
[MerRec campaign statement](./guides/datasets/merrec.mdx#audience-funnel)
ranks a graph's output, searches vectors among the result, scores the union
with a trained model and counts the outcome, inside one physical plan.

## Algorithm families {/* #available-building-blocks */}

DataFusion provides SQL planning and the session APIs. Algeon adds cuDF
execution for supported relational plans and GPU UDTFs backed by
NVIDIA's GPU libraries:

| Capability | SQL interface | Current use |
| --- | --- | --- |
| Graph analysis | [`cugraph_*`](./cugraph/overview.mdx) | Graph traversal, centrality, community detection, components, similarity, core structure, and ForceAtlas2 layout. |
| Vector analysis | [`cuvs_*`](./cuvs/overview.mdx) | Exact and approximate kNN, pairwise distances, per-row top-k, KMeans, and PCA over vector columns. |
| Machine learning | [`cuml_*`](./cuml/overview.mdx) | Fit models within a query, or score features with a pretrained XGBoost, LightGBM, or Treelite forest. |

Each family returns ordinary rows, lists its installed UDTFs in its index,
and requires its build feature and session setup.

## Build and run {/* #start-exploring */}

Algeon supports Linux with an NVIDIA GPU. Follow [Build & Test](./build/overview.md)
for prerequisites and build instructions, then choose an integration:

- **Rust application:** install Algeon in an [embedded DataFusion session](./integration/datafusion-session.mdx).
- **SQL client:** run the [Arrow Flight SQL server](./integration/flight-sql-server.mdx) and connect with ADBC.

Before adding a UDTF to a query,
[discover and validate it](./guides/gpu-udtf-discovery.mdx) against
registered tables; when an attempt fails,
[structured errors](./integration/handling-errors.mdx) carry diagnostic
fields and retry guidance. [Introducing Algeon](/blog/introducing-algeon)
describes the motivation and application scenarios.

## DataFusion integration {/* #how-it-fits-into-datafusion */}

<ArchitectureDiagram
  caption={<>A query enters through the interface you already use. Algeon's
  DataFusion optimizer rule replaces supported plan candidates with GPU
  execution in the same process, and results return as ordinary Arrow
  batches. Table data comes from Parquet files on local disk or in
  S3-compatible object storage.</>}
/>

The [execution mode](./integration/datafusion-session.mdx#choose-an-execution-mode)
sets how much relational SQL joins the GPU. By default, supported candidates
run on cuDF and the rest keeps its DataFusion CPU plan with the same results;
`functions_only` keeps ordinary SQL on the CPU around explicit GPU UDTFs, and
`native_required` rejects a plan that still contains CPU operators. Explicit
GPU UDTFs have no CPU fallback, and once GPU execution starts a failure
returns as a structured error and is never replayed on CPU. The
[Design](./design/index.mdx) pages follow a query from SQL to GPU columns and
back.

:::warning[Experimental]

APIs and query behavior may change incompatibly. Stability and result
verification remain incomplete; compare outputs against trusted reference results.
The [roadmap](./reference/roadmap.md) lists what changes next.

:::

## Scope and non-goals {/* #scope */}

Algeon is a single-process engine for exploratory analysis over a working
set that fits one GPU.

- A query runs on one GPU inside a fixed memory
  [grant](./design/admission.mdx#device-profiles-and-grants), with no
  spilling; graph construction and algorithm scratch space count toward the
  grant. Spilling and multi-GPU execution are
  [longer-term roadmap items](./reference/roadmap.md#longer-term).
- GPU scans read Parquet from local disk or S3-compatible storage, read-only,
  and cover a [subset of SQL](./reference/native-sql-support.mdx) and
  [data types](./reference/data-type-support.md). Lakehouse catalogs, Iceberg
  first, are the [next source on the roadmap](./reference/roadmap.md#mid-term).
- Indexes, fitted models and graphs live within one statement; a bounded
  server can [cache graphs](./cugraph/overview.mdx#reuse-in-bounded-servers).
- The design target is an agent or analyst running many ad-hoc OLAP queries
  against a shared GPU and revising most of them. The engine owns the
  physical plan, failures return structured errors with retry guidance, and
  admission protects the device. Taking a 100 ms query to 1 ms is outside
  that effort; see the [design priorities](./design/index.mdx#priorities).
- DataFusion is the only integration, with no Substrait input and no plan
  for a wide set of engines. Algeon is a Rust library meant to be embedded
  in a backend service and modified by the team that runs it, and the Flight
  SQL server is that library behind a network interface.
