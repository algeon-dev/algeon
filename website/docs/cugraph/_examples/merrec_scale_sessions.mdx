This example runs on the full [MerRec marketplace dataset](../../guides/datasets/merrec.mdx):
1,268,092,738 events from May through October 2023.

### Is `session_id` safe to use as a per-user session key?

The events table has a `session_id` column, and grouping by it looks like
the natural way to build sessions. This query checks that assumption with
a graph. Every October user and every session ID becomes a vertex, and an
edge joins a user to each session ID that appears in their events. If a
session ID belonged to one user, every connected component would hold
exactly one user. Graph vertices can be strings, so a user vertex is
`user:` followed by the user ID and a session vertex is the 64-character
session ID itself; the two kinds cannot collide.

```sql
WITH october AS (
  SELECT DISTINCT user_id, session_id
  FROM merrec_events
  WHERE event_time >= TIMESTAMP '2023-10-01 00:00:00'
), components AS (
  SELECT vertex, component FROM cugraph_weakly_connected_components(
    edges => (SELECT CONCAT('user:', CAST(user_id AS VARCHAR)) AS src, session_id AS dst FROM october),
    directed => false)
), user_components AS (
  SELECT component, COUNT(*) AS users FROM components WHERE STARTS_WITH(vertex, 'user:') GROUP BY component
)
SELECT CASE WHEN users = 1 THEN '1 user'
            WHEN users <= 10 THEN '2-10 users'
            WHEN users <= 1000 THEN '11-1,000 users'
            ELSE 'over 1,000 users' END AS component_size,
       COUNT(*) AS components, SUM(users) AS users, MAX(users) AS largest
FROM user_components
GROUP BY 1
ORDER BY largest;
```

| Component size | Components | Users | Largest |
|---|---:|---:|---:|
| 1 user | 335,591 | 335,591 | 1 |
| 2-10 users | 360 | 728 | 4 |
| over 1,000 users | 1 | 2,649,977 | 2,649,977 |

One component links 2,649,977 of October's 2,986,296 users through shared
session IDs. Only 335,591 users have session IDs that no one else uses.
Across all six months, 15,138,756 of the 25,864,474 distinct session IDs
appear for more than one user, and one ID appears for 54 users. Session
analysis on this dataset must therefore group by `(user_id, session_id)`.
The query does not show why IDs repeat; that is a property of the source
data.
