### How many papers are within two citation steps of AlexNet, VGG, or ResNet?

The three papers form one source set. Each result's distance is the number of
reverse citation steps from its nearest source. Title and year identify the
2016 ResNet record because a 2015 preprint shares its title.

```sql
CREATE OR REPLACE VIEW cnn_founders AS
SELECT paper_id AS vertex FROM papers
WHERE (title = 'ImageNet Classification with Deep Convolutional Neural Networks' AND year = 2012)
   OR (title = 'VERY DEEP CONVOLUTIONAL NETWORKS FOR LARGE-SCALE IMAGE RECOGNITION' AND year = 2014)
   OR (title = 'Deep Residual Learning for Image Recognition' AND year = 2016);

SELECT b.distance, COUNT(*) AS papers
FROM cugraph_bfs(
  edges => (SELECT dst AS src, src AS dst FROM citation_edges_by_dst),
  sources => (SELECT vertex FROM cnn_founders), depth_limit => 2,
  output_mode => 'vertices') b
JOIN papers p ON p.paper_id = b.vertex
WHERE b.reachable
GROUP BY b.distance
ORDER BY b.distance;
```

| distance | papers |
|---|---|
| 0 | 3 |
| 1 | 28,776 |
| 2 | 69,038 |

### Would using paper titles as graph IDs merge different records?

This query compares record IDs with titles in the reference ancestry of
*Attention Is All You Need*, then runs BFS with string titles as vertex IDs.
The count shows whether this subgraph contains repeated titles. Identical
titles alone do not establish that records describe the same work.

```sql
CREATE OR REPLACE VIEW attention_ancestry AS
WITH origins AS (
  SELECT paper_id FROM papers
  WHERE title = 'Attention is all you need' AND year = 2017
  UNION ALL
  SELECT e.dst FROM citation_edges e
  JOIN papers p ON p.paper_id = e.src
  WHERE p.title = 'Attention is all you need' AND p.year = 2017)
SELECT e.src, e.dst
FROM citation_edges e JOIN origins o ON o.paper_id = e.src;

SELECT COUNT(DISTINCT n.paper_id) AS papers, COUNT(DISTINCT p.title) AS titles
FROM (SELECT src AS paper_id FROM attention_ancestry
      UNION SELECT dst FROM attention_ancestry) n
JOIN papers p ON p.paper_id = n.paper_id;

SELECT b.distance, b.vertex
FROM cugraph_bfs(
  edges => (SELECT ps.title AS src, pd.title AS dst
            FROM attention_ancestry a
            JOIN papers ps ON ps.paper_id = a.src
            JOIN papers pd ON pd.paper_id = a.dst),
  source_vertex => 'Attention is all you need', output_mode => 'vertices') b
WHERE b.distance <= 1
ORDER BY b.distance, b.vertex
LIMIT 6;
```

| papers | titles |
|---|---|
| 370 | 358 |

This subgraph has 370 records and 358 distinct titles. A title-keyed graph
collapses records that share a title, including unrelated works when their
titles collide. Use that grouping only when merging every record with the same
title matches the question. Here BFS returns the title as a `Utf8` vertex:

| distance | vertex |
|---|---|
| 0 | Attention is all you need |
| 1 | A Decomposable Attention Model for Natural Language Inference |
| 1 | A Deep Reinforced Model for Abstractive Summarization |
| 1 | Adam: A Method for Stochastic Optimization |
| 1 | Deep Recurrent Models with Fast-Forward Connections for Neural Machine Translation |
| 1 | Deep Residual Learning for Image Recognition |

String graphs reject `edge_id` columns and edge-ID predicate relations. See the
[Vertex ID support](../graph-options.mdx#vertex-id-support-by-udtf) matrix.

### How far are several target papers from one source?

Join targets to the default `vertices` result to retain every requested ID,
including targets absent from the graph. This example follows references from
BERT for at most four hops. A null distance means the search did not reach the
target within that depth; it does not establish that the target is unreachable
in the full graph.

```sql
WITH bfs AS (
  SELECT vertex, distance
  FROM cugraph_bfs(
    edges => (SELECT src, dst FROM citation_edges),
    sources => (SELECT paper_id AS vertex FROM papers
                WHERE title = 'BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding'
                  AND year = 2018),
    depth_limit => 4)
), targets AS (
  SELECT paper_id AS vertex FROM papers
  WHERE (title = 'Attention is all you need' AND year = 2017)
     OR (title = 'Long short-term memory' AND year = 1997)
), target_distances AS (
  SELECT t.vertex AS target, b.distance,
         b.distance IS NOT NULL AS reachable
  FROM targets t LEFT JOIN bfs b ON b.vertex = t.vertex
)
SELECT target, distance, reachable
FROM target_distances
ORDER BY target;
```

To return one summary row, replace the final `SELECT` with
`SELECT COUNT(distance) > 0 AS target_found, MIN(distance) AS target_distance
FROM target_distances`. The summary describes the target set rather than each
BFS vertex. The search completes the specified depth or exhausts the frontier,
which can process more vertices than stopping at the first target hit.
Latency and memory use can therefore differ from the former target calls.

Calls using `output_mode => 'normalized'` or `'raw'` must switch to `vertices`
or omit `output_mode`. Use `distance IS NULL` or `reachable` instead of comparing
sentinels. Remove `return_target_info`; express summaries with the join and
aggregate above. Use `target_vertices` inside `cugraph_bfs` only with
`output_mode => 'path'`, which requires exactly one target row at execution.
