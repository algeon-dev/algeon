# Demo Dataset: Citation Network

The per-algorithm **Examples** in this section all run against one dataset: the
[DBLP / AMiner Citation Network V12](https://www.kaggle.com/datasets/mathurinache/citation-network-dataset),
containing **4,894,081 papers** connected by **45,564,149 directed citation edges**
(`src` cites `dst`). It is small enough to fit on one GPU and detailed enough to
support substantive queries: every vertex is a paper with a title, year, venue,
authors, and fields of study, so every algorithm result can be joined back to
human-readable metadata.

:::note[Dataset vintage]
The V12 snapshot was compiled on **2020-04-09**, so this corpus is old by
design: it stops in early 2020, misses everything published since, and its
citation counts reflect that moment rather than today. Treat every example
result as a property of this fixed snapshot, not a statement about the current
literature.
:::

The revised queries were executed on **2026-09-26** against the direct-Parquet
tables below. Displayed tables are representative captures; tied rows,
community membership, layout coordinates, and shortest-path predecessors can
vary between executions. Jaccard, Overlap, and Sørensen scores were also checked
against independent calculations from the reference sets. The
[Cosine example](./functions/similarity/cugraph_cosine.mdx#examples) records a
known normalization error and withholds its incorrect ranking.

## Tables

The primary demo source is the local Iceberg REST namespace
`lake.citation_network`. It contains five Iceberg tables loaded from the
Parquet files generated by `fixture/graph/dblp_ingest.py` (see
`fixture/README.md` in the repository):

| Table | Rows | One row is |
|---|---|---|
| `citation_edges` | 45.6M | a citation edge (`src`, `dst`, `weight`=1.0), clustered by `src` |
| `citation_edges_by_dst` | 45.6M | the same edges, clustered by `dst` for reverse traversal |
| `papers` | 4.9M | a paper: `paper_id`, `title`, `year`, `venue`, `n_citation`, `n_references`, `primary_fos`, … |
| `paper_authors` | 14.9M | a paper-author link |
| `paper_fos` | 45.0M | a paper-field-of-study link |

Load the namespace with the local REST/RustFS stack:

```bash
docker compose -f fixture/iceberg-local/docker-compose.yml up -d
fixture/fixture.sh iceberg rest load \
  --workload citation_network \
  --load-mode add-files
```

`add-files` stages the generated Parquet files into RustFS and registers them
with Iceberg in place. Do not delete the staging prefix while the REST fixture
metadata is live. The local REST fixture stores catalog metadata in ephemeral
SQLite, so rerun the loader after every fresh `docker compose up`.

To serve those tables through the Flight SQL server, use the
[citation demo server recipe](../integration/flight-sql-server.mdx#start-the-citation-demo-server).
The server recipe enables cuGraph SQL, binds to localhost, and installs the
workspace overlay that makes these tables available as unqualified names.

### Keep example DDL in the local workspace

The workspace overlay makes unqualified names such as `citation_edges` and
`papers` resolve through to `lake.citation_network.*`, while interactive DDL
stays local to `datafusion.public`. Every example statement that creates a name
uses `CREATE OR REPLACE`, so repeat runs can replace prior workspace state, and
pages that share a name (several define `ai_nodes` and `ai_edges`) overwrite
each other instead of failing. SQL-defined subgraphs and seed selections are views.
`CREATE OR REPLACE TABLE ... AS` is reserved for a snapshot of
non-deterministic algorithm output that later statements read more than once
(`scc_snapshot`, `wcc_snapshot`, `initial_layout`), shared algorithm scores
(`hits_snapshot`), an algorithm output chained
into another `cugraph_*` call (`kcore30_edges`), and an Int32
renumbering map (see below). These tables provide reusable results for later
statements. CTAS executes its input eagerly, downloads cuGraph output into Arrow
batches, and registers a DataFusion `MemTable` in the local workspace. The
collected batches occupy host RAM, and a later native scan uploads the required
data to the GPU again. This path has no disk sink or SQL-accessible GPU-resident
table. Include CTAS execution and result collection in end-to-end timing. The
table does not write back to the Iceberg source catalog.

For direct-Parquet debugging without the REST catalog, start the server with
Iceberg disabled (`ALGEON_RUN_SERVER_ICEBERG=0` in the
[server recipe](../integration/flight-sql-server.mdx#build-and-start), plus
`ALGEON_SERVER_CUGRAPH_ENABLED=true`) and register the same logical names,
where `<data>` is the absolute path of `fixture/graph/citation_network/v1`:

```sql
CREATE OR REPLACE EXTERNAL TABLE citation_edges STORED AS PARQUET LOCATION '<data>/parquet/edges_by_src.parquet';
CREATE OR REPLACE EXTERNAL TABLE citation_edges_by_dst STORED AS PARQUET LOCATION '<data>/parquet/edges_by_dst.parquet';
CREATE OR REPLACE EXTERNAL TABLE papers STORED AS PARQUET LOCATION '<data>/parquet/profiles_by_paper_id.parquet';
CREATE OR REPLACE EXTERNAL TABLE paper_authors STORED AS PARQUET LOCATION '<data>/parquet/paper_authors.parquet';
CREATE OR REPLACE EXTERNAL TABLE paper_fos STORED AS PARQUET LOCATION '<data>/parquet/paper_fos.parquet';
```

AWS Glue can serve the same table layout for remote demos, but it requires an
AWS account, a warehouse bucket, and credential setup. The local REST catalog is
the reproducible path for the website examples.

## Int32 renumbering for cuGraph C API algorithms

Two cuGraph C API algorithms (`cugraph_spectral_modularity_maximization`,
`cugraph_minimum_spanning_tree`) require
**Int32 vertex columns**. AMiner paper ids do not fit: 42% of them exceed
2,147,483,647 (the maximum id is 3,009,038,462), so a plain `CAST` overflows.
The examples renumber in SQL instead: materialize a dense mapping once, then
join it onto the edge view:

```sql
CREATE OR REPLACE TABLE my_vertex_ids AS
SELECT paper_id, CAST(ROW_NUMBER() OVER (ORDER BY paper_id) AS INT) AS vid
FROM (SELECT src AS paper_id FROM my_edges UNION SELECT dst FROM my_edges);
```

The examples compute the dense map once, then reuse it to map edge endpoints
and join result ids back to `papers`.

## From question to answer

For “Do citation communities match the research fields in our catalog?”, a
backend agent can map papers and field labels to `papers.paper_id`,
`papers.year`, and `papers.primary_fos`, and citations to
`citation_edges.src` and `citation_edges.dst` (`src` cites `dst`). The SQL
filters `papers` to selected AI field labels from 2010 onward, then keeps only
citations whose source and destination both belong to that set. It passes the
resulting edge view to `cugraph_louvain`, joins each returned `vertex` to
`papers.paper_id`, and groups by community `partition` and `primary_fos`.

The query reports the three most common field labels in each selected
community larger than 2,500 papers, with the community size and label counts.
Those rows let a reader compare the citation-based grouping with the catalog's
labels for this selected population.

The Jaccard and Overlap examples compare bibliographies with undirected
similarity functions. Their edge views keep `src` as a positive paper ID and
negate `dst` to create a negative reference-role ID (`-e.dst`). This role split
makes each paper's outgoing bibliography its neighborhood; incoming citations
connect through the separate negative reference-role ID. See the local
[Jaccard example](./functions/similarity/cugraph_jaccard.mdx#examples) and
[Overlap example](./functions/similarity/cugraph_overlap.mdx#examples).

## Seed papers used in the examples

The examples keep `paper_id` as the vertex domain and select seed papers with
SQL over `papers`. A title cannot serve as the vertex id of the full graph: the
4,894,081 papers carry 4,696,970 distinct titles, 193,894 titles repeat, and
one title is shared by 32 papers, so a title-keyed graph would merge those
papers into single vertices. Each seed is resolved with
`WHERE title = '…' AND year = …`, plus `venue` where title and year still
collide, and results are joined back to `papers` for display. The
[BFS page](./functions/traversal/cugraph_bfs.mdx#would-using-paper-titles-as-graph-ids-merge-different-records)
shows what title keys do on a small subgraph.

| Paper | `paper_id` | Exact `title` in the corpus | `year` | Extra predicate |
|---|---|---|---|---|
| Transformer | `2963403868` | `Attention is all you need` | 2017 | |
| BERT | `2896457183` | `BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding` | 2018 | |
| AlexNet | `2163605009` | `ImageNet Classification with Deep Convolutional Neural Networks` | 2012 | |
| VGG | `1686810756` | `VERY DEEP CONVOLUTIONAL NETWORKS FOR LARGE-SCALE IMAGE RECOGNITION` | 2014 | |
| ResNet | `2194775991` | `Deep Residual Learning for Image Recognition` | 2016 | |
| LSTM | `2064675550` | `Long short-term memory` | 1997 | |
| PageRank | `2066636486` | `The anatomy of a large-scale hypertextual Web search engine` | 1998 | `venue = 'The Web Conference'` |

String equality is exact and case-sensitive: `Attention Is All You Need`
(capitalized) matches a separate arXiv record with a different id. Copy titles
from this table or from a query on `papers`, not from the published paper.

## Two practical caveats

### Snapshot non-deterministic labels before self-joining

Component and community ids (`label`, `partition`) are assigned per execution.
A view retains the logical definition of its `cugraph_*` call, and a later scan
can execute that definition again. A query plan may share work within one
statement. A view provides no fixed snapshot guarantee. Use the CTAS pattern
above when later statements need to reuse the same label assignment.

### `n_citation` counts the whole world, in-degree counts this corpus

`papers.n_citation` is AMiner's global citation count; an in-graph degree only
counts edges present in this dataset. The [in-degree example](./functions/structure/cugraph_in_degrees_all.mdx)
measures exactly that gap.
