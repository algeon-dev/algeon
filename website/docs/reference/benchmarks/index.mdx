# Benchmarks

## GPU algorithms

The GPU algorithms behind the `cugraph_*`, `cuvs_*` and `cuml_*` UDTFs are
NVIDIA's libraries, and NVIDIA publishes their benchmarks. Algeon has not
re-run them, and a UDTF call adds SQL planning, graph or index construction
and result transfer on top of the kernel time they measure. Read them at
the source:

- [cuGraph](https://docs.nvidia.com/cugraph/latest/nx_cugraph/benchmarks/#benchmarks):
  speedup of nx-cugraph over NetworkX per algorithm on four graphs up to
  69 million edges. Centrality, community and counting algorithms gain two to
  four orders of magnitude on the large graphs; BFS and shortest paths do
  not.
- [cuVS](https://developer.nvidia.com/topics/ai/generative-ai/cuvs#section-performance):
  index build time and cost, query throughput and latency against CPU vector
  search.
- [cuML](https://docs.nvidia.com/cuml/latest/cuml-accel/benchmarks/#inference-and-transforms):
  cuml.accel against scikit-learn, umap-learn and hdbscan per estimator,
  for training, inference and transforms.

Benchmarks of the UDTFs themselves over the [demo datasets](../../guides/datasets/index.mdx)
are planned.

## Relational path

The runs below are Algeon's own: the TPC-H and TPC-DS suites at scale
factor 100, CPU path against GPU path.

### TPC-H SF100

The 22 TPC-H queries, CPU path and GPU path from the same release build
over the same Parquet fixture on an AWS g7e.4xlarge (16 vCPUs, 128 GiB, one
RTX PRO 6000, local NVMe), one warm-up and one measured iteration. All row
counts matched.
