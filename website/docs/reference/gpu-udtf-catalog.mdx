# GPU UDTF Catalog API

Three metadata UDTFs describe every cuGraph, cuVS and cuML UDTF installed in
a session, so a client or an agent can find, understand and check a call
without reading server source:

- `gpu_list_functions()` lists the installed UDTFs and whether each one is
  executable in this build and session.
- `gpu_describe_function(name)` returns one UDTF's contract: signature,
  relation roles, option schema, result schemas, examples and limitations.
- `gpu_validate_call(name, call_json)` checks a concrete call against the
  schemas of named tables or views and the UDTF's options. It reads no data
  and runs nothing on the GPU.

[Discover & Validate GPU UDTFs](../guides/gpu-udtf-discovery.mdx) walks
through the list, describe, validate and execute sequence. This page is the
schema reference. Names are exact canonical UDTF names. Provider-local
aliases are not accepted. Wrong metadata UDTF arity and nonliteral metadata
arguments are planning errors.

## gpu_list_functions

One row per installed UDTF, ordered by `function_name`, without the three
metadata UDTFs themselves. The catalog spans providers. Filter by `provider`
for the `cugraph`, `cuvs` or `cuml` subset.

```sql
SELECT function_name, provider, available, summary
FROM gpu_list_functions()
WHERE provider IN ('cugraph', 'cuvs', 'cuml')
ORDER BY function_name;
```

| Column | Type | Meaning |
| --- | --- | --- |
| `function_name` | `Utf8` | Canonical UDTF name. |
| `provider` | `Utf8` | `cugraph`, `cuvs` or `cuml`. |
| `available` | `Boolean` | Whether the UDTF can be planned for GPU execution in this build and session. |
| `unavailable_reason` | `Utf8` | Stable reason code, null when available. A UDTF whose build feature is off reports `required_feature_disabled`. |
| `signature` | `Utf8` | Canonical SQL execution signature. |
| `summary` | `Utf8` | One-line description. |
| `relation_roles_json` | `Utf8` | Ordered relation-role definitions. |

`available=true` covers the UDTF itself; the relational operators around it
are planned separately.

## gpu_describe_function(function_name)

One full descriptor row for one UDTF. There is no compact mode. Project the
columns you need.

```sql
SELECT signature, options_schema_json, result_schemas_json
FROM gpu_describe_function('cuvs_brute_force_knn');
```

The row carries the seven `gpu_list_functions` columns plus:

| Column | Type | Meaning |
| --- | --- | --- |
| `argument_descriptions_json` | `Utf8` | Descriptions of the non-relation arguments. |
| `options_schema_json` | `Utf8` | JSON schema of the options object. |
| `result_schemas_json` | `Utf8` | Default and mode-dependent result schemas, with field semantics where available. |
| `validation_request_schema_json` | `Utf8` | JSON schema that `gpu_validate_call` accepts for this UDTF. |
| `examples_json` | `Utf8` | Quickstart, validation and execution examples. |
| `limitations_json` | `Utf8` | Known static and runtime limitations. |

Every JSON column holds valid JSON. An empty object or array is `{}` or `[]`,
never SQL `NULL`.

## gpu_validate_call(function_name, call_json)

Static validation of one call. The envelope names registered tables or views
by role; the selected UDTF owns the meaning of its roles and options.

```sql
SELECT *
FROM gpu_validate_call(
  'cuvs_kmeans',
  '{
    "relations":{"input":{"table":"embedding_vectors"}},
    "options":{"n_clusters":8}
  }'
);
```

The envelope holds `relations` and `options`. `relations` is an object keyed by the
descriptor's relation roles, each with one `table` field holding a one-, two-
or three-part DataFusion table or view reference. `options` is an object the
UDTF validates. Unknown envelope keys, roles and option keys are rejected. The
envelope never carries SQL text: to validate a derived subquery, register it
as a temporary view first.

| Column | Type | Meaning |
| --- | --- | --- |
| `valid` | `Boolean` | Whether the call is valid in this session. |
| `error_code` | `Utf8` | Stable reason code of the first problem, null when valid. |
| `message` | `Utf8` | `valid`, or every detected problem's message joined by `; `. |
| `function_name` | `Utf8` | Canonical name, or the unresolved requested name. |
| `relations_resolved` | `Boolean` | Whether every required relation resolved. |
| `normalized_call_json` | `Utf8` | The envelope after defaults and canonicalization. |
| `output_schema_json` | `Utf8` | Concrete output schema when it can be derived. |
| `would_execute_gpu` | `Boolean` | Whether this call would target GPU execution after static planning. |
| `details_json` | `Utf8` | Per-relation and provider-specific validation facts. |

An unknown UDTF or an invalid call returns one row with `valid=false`. An
unavailable UDTF reports its `unavailable_reason` before anything else.
Otherwise the row lists, from one pass, every unresolved relation, every
option error and the relation schema errors that do not depend on a rejected
option. `error_code` and `details_json` describe the first. A check that depends on a rejected option,
such as a required option that failed its own check, runs once that option is
valid. `details_json` locates the first problem with `path` and, when present,
`argument`, `relation_role` and `field`.

A table function whose name starts with `cugraph_`, `cuvs_`, `cuml_` or
`gpu_` but names no installed function fails planning with `object_not_found`.
The message names the closest registered name when one is near enough and
points to `gpu_list_functions()`. A call to `cugraph_page_rank` fails with:

```text
unknown GPU function cugraph_page_rank; closest registered name: cugraph_pagerank; gpu_list_functions() lists every installed function
```

Validation checks that the UDTF exists, resolves every required relation,
validates the relation bindings, columns, types, dimensions, conditional
arguments and option values, applies defaults, and derives the output schema
when it can. Source-vertex existence, vector uniformity and cardinality are
checked at execution, and an admitted call that exceeds its memory grant fails
there with an allocation error. `would_execute_gpu` covers this one call;
[GPU coverage validation](../integration/gpu-coverage-validation.mdx) covers
the whole query.
