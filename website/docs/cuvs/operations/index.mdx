# Functions

All cuVS functions consume parenthesized relation-valued subqueries and return
ordinary relations that can be joined, filtered, aggregated, exported, or used
by a later GPU SQL operator in the same statement. Their exact input and
lifecycle contracts differ, so choose the function by the work it does within
one evaluated query rather than by a generic "vector operation" label.

These are computation calls, not persistent artifact-management APIs: the
current integration has no cross-statement cuVS cache for indexes, fitted
models, transforms, or result relations. See [cuVS SQL API](../overview.mdx)
for the bounded-preflight and server-cache boundary.

## Vector Search

- [Brute-force kNN](./cuvs_brute_force_knn.mdx) performs exact,
  query-local nearest-neighbor search. Use it for filtered candidate generation
  and exact batch reranking; it does not create a persistent ANN index.

## Clustering

- [KMeans](./cuvs_kmeans.mdx) fits and assigns clusters in one SQL
  statement. Its `cluster_id` values are query-local labels, not stable topic
  or business identifiers.

## Dimensionality Reduction

- [PCA](./cuvs_pca.mdx) fits and transforms its evaluated input in
  one SQL statement. The emitted `pc_0` through `pc_<n_components - 1>` fields
  depend on the literal component count; no reusable transform is returned.
