# CAGRA

UDTF: `cuvs_cagra`

Official cuVS reference: [C API](https://docs.nvidia.com/cuvs/api-reference/c-api-neighbors-cagra)

Query-local graph approximate nearest-neighbor search.

## Quickstart

The call below expects the registered relations `dataset_vectors` (the `dataset` role) and `query_vectors` (the `queries` role), each passed as a parenthesized `SELECT` subquery.

```sql
SELECT *
FROM cuvs_cagra(
  dataset => (SELECT id, d0, d1 FROM dataset_vectors),
  queries => (SELECT id, d0, d1 FROM query_vectors),
  k => 8,
  metric => 'l2_expanded',
  graph_degree => 32,
  intermediate_graph_degree => 64
)
ORDER BY query_ordinal, rank;
```

### Vector binding shapes

Each relation subquery must project an `id` field followed by either one or more feature fields of a supported element type (`Float32`, `Int8`, `UInt8`) or one list field of a supported element type, under any name.

For wide vectors, the projection order defines the feature dimensions. A list vector relation must contain no feature field beside `id` and its list field. Nullable field types are accepted. A null ID, feature value, list row, or list element fails the query.

## Limits

- Builds and frees its graph and padded dataset during each query execution; executions never share an index.
- Approximate search may return fewer than k neighbors; missing (query, rank) rows are omitted and valid ranks remain contiguous.
- The dataset must be non-empty, k and intermediate_graph_degree must be less than or equal to its row count, and graph_degree must be less than intermediate_graph_degree.
- k must not exceed itopk_size. single_cta requires itopk_size no greater than 1024. cosine cannot use nn_descent.
- Dataset and query dimensions and element types must match.
- Neighbors and distances can differ slightly between runs, because graph construction orders edges by atomic arrival; there is no seed option.
