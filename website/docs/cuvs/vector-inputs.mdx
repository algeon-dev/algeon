# Vector Inputs

All eight cuVS UDTFs take relation arguments as parenthesized `SELECT`
subqueries. Each subquery remains a planner child. For `gpu_validate_call`,
register a table or view with the same schema; metadata validation does not
evaluate rows.

## Relation identity

Every `dataset`, `queries`, `x`, `y`, or `input` binding names a logical ID
column:

- The ID must be non-null `Int32`, `Int64`, `Utf8`, `LargeUtf8`, or `Utf8View`.
- IDs may repeat. Result ordinals disambiguate physical rows with equal IDs.
- A subquery's top-level `ORDER BY` fixes the order its rows are numbered in.
  Sort keys must be output columns of the subquery, by name or 1-based
  position; other keys are rejected with `input_ordering_key_not_projected`
  unless `LIMIT`, `OFFSET`, or `FETCH` bounds the rows. Without a top-level
  `ORDER BY`, row order is unspecified, and rows that tie on every key have no
  stable order.
- The ID comes from a relation field. Name the field in each JSON binding with
  `"id"`; cuVS does not assign a logical ID from row position.

## Dense-vector binding shapes

Each binding chooses one vector shape. Feature order defines dimension order.

### Wide columns

```json
{"id":"paper_id","vector":{"columns":["d0","d1","d2"]}}
```

- `columns` contains at least one unique, non-empty column name.
- Each selected feature column is non-null. All columns in the binding share
  one supported element type.
- The listed order defines the vector dimensions.

### One list column

```json
{"id":"paper_id","vector":{"column":"embedding"}}
```

- `embedding` is non-null `FixedSizeList<T, D>`, `List<T>`, or `LargeList<T>`
  with a supported element type `T`.
- List elements are non-null. `FixedSizeList` has a positive dimension `D`.
- Variable-width `List` and `LargeList` rows must have one uniform, positive
  dimension after evaluation.

`WHERE column IS NOT NULL` filters rows but does not make a column
non-nullable in the schema, so it cannot satisfy the non-null feature
requirements above. Use `COALESCE(column, CAST(0 AS REAL))` or another
null-free expression in the subquery projection instead.

## Element types

Floating vector values must be finite; `NaN` and infinity are rejected.
Integer elements have no finiteness requirement. All vector bindings in one
call share an element type and dimension. cuVS does not cast vector elements
implicitly. Use `CAST` in a relation subquery to select a supported type.
`Float16` is unsupported because cuDF has no Float16 representation.

Brute-force kNN and the three ANN UDTFs return `Float32` distance values.
Pairwise `distance` follows the input float width (`Float32` or `Float64`).
KMeans `cluster_id` remains `Int32`.

## What validation can prove

`gpu_validate_call` checks the versioned JSON envelope, relation existence,
field names, static types, binding shapes, duplicate wide-column names,
matching element types, valid element/metric pairs, and scalar option ranges.
It does not evaluate subqueries, scan values, or launch cuVS. Known relation
cardinalities and fixed-size dimensions may also be checked during SQL
planning; the following constraints are checked against evaluated rows when
those facts are not known statically:

| Operation | Evaluated-relation requirements |
| --- | --- |
| Brute-force kNN | Dataset must be non-empty; `k` cannot exceed dataset rows. Dataset and query dimensions must match. Empty queries may produce an empty result with the declared schema. |
| IVF-Flat | Dataset must be non-empty; `k` and `n_lists` cannot exceed dataset rows. Cosine requires at least two dimensions. With incomplete probes, fewer than `k` neighbors may be returned. |
| IVF-PQ | Dataset must be non-empty; `k` and `n_lists` cannot exceed dataset rows. Cosine requires at least two dimensions. Compression can omit neighbors even when all lists are probed. |
| CAGRA | Dataset must be non-empty; `k` and graph degrees are constrained by dataset rows. Search may omit missing neighbors. |
| Pairwise distance | Empty `x` or `y` returns an empty result with the declared schema. Output rows equal `x` rows multiplied by `y` rows and are bounded by the query allocation cap. |
| Vector Top-K | `k` cannot exceed vector dimension. For variable-width lists, that dimension is checked after evaluation. Empty input returns an empty result. |
| KMeans | Input must be non-empty; `n_clusters` cannot exceed evaluated input rows. |
| PCA | Input needs at least two rows and two dimensions; `n_components` cannot exceed evaluated dimension. |

Scalar checks do not require evaluated rows: IVF search requires
`n_probes <= n_lists`; CAGRA requires `k <= itopk_size` and
`intermediate_graph_degree > graph_degree`. CAGRA also rejects cosine with
`nn_descent`, and `single_cta` requires `itopk_size <= 1024`. A nonzero IVF-PQ
`pq_dim * pq_bits` must be divisible by 8.

cuVS calls execute inside the admitted query memory domain. Allocation beyond
the configured cap fails at the allocator. See
[Integrating Algeon](../integration/overview.mdx) for embedded and Flight SQL
setup.
