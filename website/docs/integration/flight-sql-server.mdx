# Flight SQL Server

Run the standalone server when clients need a remote Arrow Flight SQL
endpoint instead of an embedded Rust API. It builds one shared GPU backend,
installs the cuVS UDTFs on every session (and the cuGraph UDTFs
when [enabled in its configuration](./configuration.mdx#gpu-sql-udtfs)),
and serves ordinary Arrow results to any ADBC or Flight SQL client. Its
embeddable implementation and public API live in
`algeon_datafusion::server`; `crates/algeon-server` is the standalone launcher.

## Build and start

Build the `algeon-server` package and its `algeon_server` binary:

```bash
cargo build --workspace --all-features --release --bin algeon_server
```

Every selected GPU needs an explicit device profile. For a single-GPU local
server, create `server.toml` in the repository root:

```toml
[[admission.device_profiles]]
device_ordinal = 0
```

Then start the server on localhost:

```bash
export ALGEON_SERVER_CONFIG_FILE="$PWD/server.toml"
export ALGEON_SERVER_BIND=127.0.0.1:50051

flock /tmp/cudf-gpu.lock "${CARGO_TARGET_DIR:-target}/release/algeon_server"
```

From another terminal, verify the endpoint with the repository client:

```bash
cargo run -p tools --all-features -- \
  flight-sql-query http://127.0.0.1:50051 "SELECT 1 AS one"
```

The expected result is a column named `one` containing `1`. Authentication is
disabled by default, so keep this setup on a trusted local interface. See
[Configuration](./configuration.mdx) before exposing the endpoint or selecting
more GPUs.

To keep ordinary SQL on DataFusion CPU while explicit cuGraph and cuVS calls
run on GPU, set `ALGEON_SERVER_EXECUTION_MODE=functions_only` before startup.
The default is `native_preferred`; see
[Execution mode](./configuration.mdx#execution-mode) for all three modes and
their TOML equivalents.

## Start the citation demo server

The [citation investigation](../guides/datasets/citation-network.mdx) uses
Parquet files produced by the
[citation fixture](https://github.com/algeon-dev/algeon/blob/main/fixture/demo/citation_network/README.md).
With those files available, enable cuGraph in the server configuration above
before starting it:

```bash
export ALGEON_SERVER_CUGRAPH_ENABLED=true
```

Run the server from the repository root. In a connected SQL client, register
the paper records and the two sort orders of the citation edges:

```sql
CREATE OR REPLACE EXTERNAL TABLE citation_edges
STORED AS PARQUET LOCATION 'fixture/demo/citation_network/v1/parquet/edges_by_src.parquet';
CREATE OR REPLACE EXTERNAL TABLE citation_edges_by_dst
STORED AS PARQUET LOCATION 'fixture/demo/citation_network/v1/parquet/edges_by_dst.parquet';
CREATE OR REPLACE EXTERNAL TABLE papers
STORED AS PARQUET LOCATION 'fixture/demo/citation_network/v1/parquet/profiles_by_paper_id.parquet';
```

Submit each statement separately. The three tables supply the citation-path,
bibliography and community queries on the investigation page. Examples that
use author or field links also need these registrations:

```sql
CREATE OR REPLACE EXTERNAL TABLE paper_authors
STORED AS PARQUET LOCATION 'fixture/demo/citation_network/v1/parquet/paper_authors.parquet';
CREATE OR REPLACE EXTERNAL TABLE paper_fos
STORED AS PARQUET LOCATION 'fixture/demo/citation_network/v1/parquet/paper_fos.parquet';
```

Registrations last until the server stops. The saved SQL includes any
additional views that its algorithm inputs require. The default
`native_preferred` mode supports the bibliography example's mixed execution
path; inspect a changed query with
[GPU coverage validation](./gpu-coverage-validation.mdx).

## Connect with ADBC

Use an [Apache Arrow ADBC Flight SQL
driver](https://arrow.apache.org/adbc/current/driver/flight_sql.html) from
application code. The Python DB-API wrapper requires both the Flight SQL driver
and PyArrow:

```bash
python -m pip install adbc-driver-flightsql pyarrow
```

```python
from adbc_driver_flightsql import dbapi


with dbapi.connect(uri="grpc://127.0.0.1:50051") as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT 1 AS one")
        result = cur.fetch_arrow_table()
```

The same endpoint works with other ADBC language bindings. Keep pooling,
timeouts, authentication, and result conversion in the client service.

## Connection loss and result backpressure {/* #connection-loss */}

The server sends an HTTP/2 keepalive ping after 30 seconds without inbound
traffic. An acknowledgement must arrive within 10 seconds; otherwise the
connection closes. The same settings apply when the server binds its address
and when an embedded caller supplies a prebound listener. Connection loss
drops the Flight result stream, cancels its attempt, and releases the GPU grant
after native cleanup completes. Each statement registers a cancellation token
derived from the server's shutdown token; when it fires, the next poll of the
result body cancels the attempt and drops the inner stream (see [Completion and
resident data](../design/admission.mdx#resident-handoff-and-release)).

A client that acknowledges pings but stops reading results keeps its query
under output backpressure and retains its grant until the stream ends or is
canceled. Result chunks are at most 4 MiB, and an unread result probably
holds back further polls through HTTP/2 flow control. Keepalive sets no query
idle deadline. Clients should consume or cancel result streams before
returning a connection to their pool.

## Use an interactive client

Choose either client for an interactive session.

### DataBow

[`databow`](https://github.com/columnar-tech/databow) exercises the ADBC driver
path:

```bash
databow --driver flightsql --uri grpc://127.0.0.1:50051
```

### arrow_cli

[`arrow_cli`](https://github.com/sundy-li/arrow_cli) connects directly over
Flight SQL:

```bash
arrow_cli --host 127.0.0.1 --port 50051 --timeout 120
```

Flight SQL accepts ordinary DataFusion `SET` statements, but rejects
`SET algeon_datafusion.*`; server resource policy comes from `ServerConfig`.
GPU execution requires a CUDA-capable host and the runtime libraries for the
enabled Cargo features. In the default mode, relational candidates the server
does not select for GPU execution stay in DataFusion; a failure after GPU
execution starts is returned as a structured error and is not replayed on CPU.
Use `EXPLAIN GPU` (see
[GPU Coverage Validation](./gpu-coverage-validation.mdx)) to see which parts of
a query will run on the GPU.
