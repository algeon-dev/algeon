# Configuration

This page is the environment-variable contract for a running Nexus deployment:
the Flight SQL server's `NEXUS_SERVER_*` variables, the DataFusion session keys
read through `SessionConfig::from_env()`, and the `NEXUS_ICEBERG_*` source and
workspace settings. It groups the variables that matter most for a local graph
SQL server and for production-style Iceberg deployments.

## Server core

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_BIND` | `0.0.0.0:50051` | Flight SQL listen address. Bind `127.0.0.1` to restrict to localhost. |
| `NEXUS_SERVER_LOG` | `info` | Log level (`error`/`warn`/`info`/`debug`/`trace`). |
| `NEXUS_SERVER_CUGRAPH_ENABLED` | `false` | Register the `cugraph_*` SQL functions. Requires the `cugraph` build feature. |

## Admission

Server admission is byte-denominated and slot-bounded. The default admits two
queries, guarantees each admitted query at least `1/8` of the resolved device
budget, and derives the preferred grant from the slot guarantee and native
pipeline mode. With the default `guaranteed_minimum` policy, a lone query can
use the full device budget minus the floor reserved for remaining slots.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_MAX_CONCURRENT_QUERIES` | `2` | Preferred max GPU-native/query-service admissions. |
| `NEXUS_SERVER_MAX_IN_FLIGHT` | `2` | Compatibility alias for `NEXUS_SERVER_MAX_CONCURRENT_QUERIES`. Set only one, or set both to the same value. |
| `NEXUS_SERVER_ADMISSION_GRANT_MIN` | `0.125` | Minimum per-query grant. Accepts a fraction of device capacity or an explicit byte count. |
| `NEXUS_SERVER_ADMISSION_GRANT_WANT` | policy-derived | Preferred per-query grant when memory is available. Accepts a fraction or bytes. |
| `NEXUS_SERVER_ADMISSION_SLOT_GUARANTEE` | `guaranteed_minimum` | `guaranteed_minimum` reserves enough memory for empty slots; `optimistic` grants work-conservingly and lets large arrivals wait for memory. |
| `NEXUS_SERVER_ADMISSION_WAIT_TIMEOUT_MS` | `60000` | Maximum query-service admission wait before a structured overload error. |
| `NEXUS_SERVER_GPU_DEVICES` | `0` | Comma-separated CUDA device ordinals used for independent query placement. |

## CPU fallback bound

CPU-readable plans rejected by native lowering run on DataFusion, not through
the GPU admission ledger. Server mode bounds those fallback statements with a
separate host-side semaphore.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_CPU_FALLBACK_MAX_CONCURRENT_STATEMENTS` | `2` | Maximum concurrent CPU fallback statements. Set `0` to disable the bound. |
| `NEXUS_SERVER_CPU_FALLBACK_WAIT_TIMEOUT_MS` | `30000` | Maximum wait for a CPU fallback permit before `service_overloaded`; set `0` to wait indefinitely. |

## cuGraph defaults

These set base graph-construction defaults. Algorithm-specific defaults are
applied next, and each call's `options_json` overrides both. See
[Graph Construction Options](../cugraph/graph-options.mdx) for call-level
semantics.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_CUGRAPH_DIRECTED` | `true` | Base `directed` default. Some algorithms default to `false`; each function page shows the effective default. |
| `NEXUS_SERVER_CUGRAPH_RENUMBER` | `true` | Default `renumber`. |
| `NEXUS_SERVER_CUGRAPH_CONSTRUCTION_POLICY` | `python_cugraph` | Default edge-list construction semantics: `python_cugraph` or `raw_libcugraph`. |

## GPU memory budget

The native engine runs on the GPU, so the device budget must fit your card.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_NATIVE_MEMORY_POLICY` | `bounded` | `bounded` enforces a device budget; `unbounded` lets native execution use the whole card. |
| `NEXUS_SERVER_DEVICE_BUDGET_FRACTION` | unset | Fraction of total device memory eligible for native query budgets. `1.0` preserves the historical auto-sized `total - headroom` behavior. |
| `NEXUS_SERVER_NATIVE_DEVICE_BUDGET_BYTES` | unset | Explicit bounded planning budget in bytes. When set, the source chunk byte and row-group limits must also be set. |
| `NEXUS_SERVER_NATIVE_MAX_SOURCE_CHUNK_BYTES` | unset | Max bytes per source scan chunk. |
| `NEXUS_SERVER_NATIVE_MAX_ROW_GROUPS_PER_CHUNK` | unset | Max Parquet row groups per chunk. |

:::warning[Size the budget to your GPU]
The data-center default budget targets an RTX PRO 6000-class GPU with 96 GB
VRAM and assumes roughly 95 GiB is free for native execution. On a smaller GPU,
or when other processes reduce free VRAM, set a smaller value, for example
`NEXUS_SERVER_DEVICE_BUDGET_FRACTION=0.5`. Use
`NEXUS_SERVER_NATIVE_MEMORY_POLICY=unbounded` only for local single-query work
when the GPU is otherwise idle.
:::

## DataFusion session

DataFusion reads its own `SessionConfig::from_env()` keys. The key
`datafusion.<group>.<name>` maps to the env var by upper-casing and replacing
`.` with `_`:

| Variable | Maps to | Purpose |
| --- | --- | --- |
| `DATAFUSION_EXECUTION_BATCH_SIZE` | `datafusion.execution.batch_size` | DataFusion/fallback operator batch size (default `8192`). |
| `DATAFUSION_CATALOG_DEFAULT_CATALOG` | `datafusion.catalog.default_catalog` | Default catalog for unqualified names. |
| `DATAFUSION_CATALOG_DEFAULT_SCHEMA` | `datafusion.catalog.default_schema` | Default schema; the mutable session workspace for `CREATE VIEW` etc. |

Nexus also registers `datafusion_nexus.native.*` session keys for direct
optimizer installs. Backend-managed sessions freeze those native policy keys so
they cannot diverge from the shared admission ledger. The
`datafusion_nexus.request.*` namespace is intentionally request-scoped and stays
mutable on those embedded DataFusion sessions. Set
`datafusion_nexus.request.requested_grant_bytes` (preferred grant),
`datafusion_nexus.request.requested_grant_min_bytes` (request-scoped grant
floor: admit with at least this much or keep queueing), or
`datafusion_nexus.request.graph_raw_input_edges` (edge-count evidence for graph
memory pricing when source statistics are unavailable) through SQL or DataFusion's
session-option API after Nexus registers the extension. Flight SQL does not
support session-scoped `datafusion_nexus.*` keys through SQL `SET`; configure
server or tenant defaults instead. The server does not load request keys from a
`DATAFUSION_NEXUS_*` environment variable during startup.

## Iceberg sources and workspace overlay

The local REST catalog is the primary demo source. It exposes the five
[citation network tables](../cugraph/demo-dataset.mdx) as
`lake.citation_network.citation_edges`, `citation_edges_by_dst`, `papers`,
`paper_authors`, and `paper_fos`.

A mutable workspace overlay exposes those source tables under unqualified names
while keeping interactive DDL local to `datafusion.public`:

```bash
NEXUS_SERVER_WORKSPACE_CATALOG=datafusion \
NEXUS_SERVER_WORKSPACE_SCHEMA=public \
NEXUS_SERVER_WORKSPACE_BACKING_CATALOG=lake \
NEXUS_SERVER_WORKSPACE_BACKING_SCHEMA=citation_network \
NEXUS_SERVER_WORKSPACE_BACKING_ALIASES=citation_edges,citation_edges_by_dst,papers,paper_authors,paper_fos
```

With the overlay, `SELECT * FROM citation_edges LIMIT 10` resolves through to
`lake.citation_network.citation_edges`, and
`CREATE VIEW target_edges AS ...` writes to `datafusion.public`. CTAS snapshots
used by a few examples are local workspace tables for deterministic re-use; they
do not write to `lake.citation_network`. Fully-qualified names keep working too.

Keep `DATAFUSION_CATALOG_DEFAULT_CATALOG=datafusion` and
`DATAFUSION_CATALOG_DEFAULT_SCHEMA=public` when the backing Iceberg catalog is
read-only. If the default catalog/schema points directly at Iceberg, interactive
DDL is routed to that read-only source catalog and may fail.

AWS Glue uses the same catalog contract, but it requires an AWS account,
warehouse bucket, and credentials. The local REST configuration remains the
reproducible website path.

For Glue with `remote_kvikio`, keep the AWS region variables aligned:
`AWS_REGION` is consumed by the Iceberg/Glue catalog path, while KvikIO's
process-global S3 behavior expects `AWS_DEFAULT_REGION`. On private buckets,
setting only `AWS_REGION` can make the remote read path fail with unsigned S3
requests and 403 responses.

`remote_kvikio` selects the cuDF/KvikIO remote Parquet reader path. It is not a
local-NVMe native GDS guarantee, and KvikIO/cuFile compatibility settings can
still determine whether the effective read uses native direct storage or a
compatibility path.

A condensed Glue configuration looks like:

```bash
NEXUS_ICEBERG_CATALOG_KIND=glue \
NEXUS_ICEBERG_CATALOG_NAME=glue \
NEXUS_ICEBERG_NAMESPACE=nexus_graph \
NEXUS_ICEBERG_GLUE_CATALOG_ID=123456789012 \
NEXUS_ICEBERG_WAREHOUSE=s3://your-bucket/warehouse \
AWS_REGION=us-west-2 \
AWS_DEFAULT_REGION=us-west-2 \
NEXUS_ICEBERG_S3_REGION=us-west-2 \
NEXUS_ICEBERG_S3_CREDENTIAL_SOURCE=default_chain \
NEXUS_ICEBERG_PARQUET_READ_STRATEGY=remote_kvikio \
NEXUS_SERVER_CUGRAPH_ENABLED=true \
NEXUS_SERVER_BIND=127.0.0.1:50051 \
flock /tmp/cudf-gpu.lock bash scripts/run_server.sh
```
