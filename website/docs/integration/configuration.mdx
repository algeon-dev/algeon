# Configuration

This page is the environment-variable contract for a running Nexus deployment:
the Flight SQL server's `NEXUS_SERVER_*` variables, the DataFusion session keys
read through `SessionConfig::from_env()`, and the `NEXUS_ICEBERG_*` source and
workspace settings. It groups the variables that matter most for a local graph
SQL server and for production-style Iceberg deployments.

## Server core

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_BIND` | `0.0.0.0:50051` | Flight SQL listen address. Bind `127.0.0.1` to restrict to localhost. |
| `NEXUS_SERVER_LOG` | `info` | Log level (`error`/`warn`/`info`/`debug`/`trace`). |
| `NEXUS_SERVER_CUGRAPH_ENABLED` | `false` | Register the `cugraph_*` SQL functions. Requires the `cugraph` build feature. |
| `NEXUS_SERVER_CONFIG_FILE` | unset | Path to the TOML overlay. It is required in a GPU server deployment because it supplies the ordinal-keyed device profiles. |

## cuVS availability

cuVS has no `NEXUS_SERVER_CUVS_ENABLED` toggle. Build the server with the
`cuvs` Cargo feature to register `cuvs_*` functions, then use
`gpu_list_functions()` or `gpu_describe_function(...)` to inspect availability.
Until cuVS supplies a bounded peak-memory preflight, the server rejects
execution with structured `unsupported_operator`; it never selects a CPU
fallback or an unadmitted GPU path.

### cuVS retention

P2 has no server-configurable cross-statement GPU artifact retention. cuVS
indexes, models, transforms, and result relations stay within the admitted
query and are released with it. The persistent lakehouse byte cache described
below is filesystem storage, not a cuVS or GPU-memory cache.

## Admission

Server admission has one bounded-resource contract. Each admitted attempt gets
an immutable device-local grant; placement is capability-first and the usable
global attempt capacity is the checked sum of the configured per-device active
limits.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_ADMISSION_MAX_QUEUED_ATTEMPTS` | `64` | Bounded admission queue length. |
| `NEXUS_SERVER_ADMISSION_MAX_QUEUE_WAIT_MS` | `30000` | Maximum queue wait before a structured overload error. |
| `NEXUS_SERVER_ADMISSION_MAX_OVERTAKES_PER_WAITER` | `4` | Finite compatible-device bypass budget for a queued waiter. |
| `NEXUS_SERVER_GPU_DEVICES` | `0` | Comma-separated CUDA device ordinals used for independent query placement. |

Device-local capacity belongs only to the ordinal-keyed TOML
`admission.device_profiles` array. Each selected ordinal needs one profile;
the server rejects startup with `missing_device_profiles` when the overlay is
absent or incomplete. For one GPU, a minimal explicit deployment is:

```toml
# /etc/datafusion-nexus/server.toml
[[admission.device_profiles]]
device_ordinal = 0
memory_limit_bytes = 24_000_000_000
attempt_floor_bytes = 536_870_912
max_active_attempts = 1
source_work_per_attempt = 1
```

```bash
NEXUS_SERVER_GPU_DEVICES=0 \
NEXUS_SERVER_CONFIG_FILE=/etc/datafusion-nexus/server.toml \
flock /tmp/cudf-gpu.lock bash scripts/dev/run_server.sh
```

`memory_limit_bytes`, `backend_reserve_bytes`, `attempt_floor_bytes`,
`source_work_per_attempt`, `max_active_attempts`, `stream_pool_size`,
`worker_count`, `lane_count`, `install_telemetry`, and
`install_diagnostics` are the only accepted profile keys after
`device_ordinal`. The installation bounds `stream_pool_size`, `worker_count`,
and `lane_count` must be supplied together. Capabilities and GPU-memory
ownership are not TOML profile fields:
the embedding process resolves them when it creates the backend. The removed
scalar active-attempt, floor, and source-work environment variables, as well
as global device-capacity overrides, are rejected rather than broadcast across
heterogeneous devices.

## cuGraph defaults

These set base graph-construction defaults. Algorithm-specific defaults are
applied next, and each call's `options_json` overrides both. See
[Graph Construction Options](../cugraph/graph-options.mdx) for call-level
semantics.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_CUGRAPH_DIRECTED` | `true` | Base `directed` default. Some algorithms default to `false`; each function page shows the effective default. |
| `NEXUS_SERVER_CUGRAPH_RENUMBER` | `true` | Default `renumber`. |
| `NEXUS_SERVER_CUGRAPH_CONSTRUCTION_POLICY` | `python_cugraph` | Default edge-list construction semantics: `python_cugraph` or `raw_libcugraph`. |

## GPU memory budget

The native engine runs on the GPU, so the device budget must fit your card.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXUS_SERVER_NATIVE_DEVICE_BUDGET_BYTES` | unset | Explicit bounded planning budget in bytes. When set, the source chunk byte and row-group limits must also be set. |
| `NEXUS_SERVER_NATIVE_MAX_SOURCE_CHUNK_BYTES` | unset | Max bytes per source scan chunk. |
| `NEXUS_SERVER_NATIVE_MAX_ROW_GROUPS_PER_CHUNK` | unset | Max Parquet row groups per chunk. |
| `NEXUS_SERVER_NATIVE_STATISTICAL_AGGREGATE_EXECUTION_MODE` | `datafusion_exact_host_welford` | Exact host Welford parity or `gpu_native_tolerant` statistical execution. |

:::warning[Leave deployment headroom]
For automatic capacity, the server resolves every claimed GPU independently
from that device's own profile; it never inherits GPU 0's budget. The 256 MiB
native value is only an unadmitted planning placeholder. These calculations
use total rather than live free memory and do not account for other processes.
Set `memory_limit_bytes` or `backend_reserve_bytes` on each device profile when
the deployment needs more headroom.
:::

The P2 controller has no cross-query GPU cache capacity setting or runtime
diagnostic. The persistent lakehouse byte cache described below is separate
from GPU device memory.

## DataFusion session

DataFusion reads its own `SessionConfig::from_env()` keys. The key
`datafusion.<group>.<name>` maps to the env var by upper-casing and replacing
`.` with `_`:

| Variable | Maps to | Purpose |
| --- | --- | --- |
| `DATAFUSION_EXECUTION_BATCH_SIZE` | `datafusion.execution.batch_size` | DataFusion/fallback operator batch size (default `8192`). |
| `DATAFUSION_CATALOG_DEFAULT_CATALOG` | `datafusion.catalog.default_catalog` | Default catalog for unqualified names. |
| `DATAFUSION_CATALOG_DEFAULT_SCHEMA` | `datafusion.catalog.default_schema` | Default schema; the mutable session workspace for `CREATE VIEW` etc. |

Nexus also registers `datafusion_nexus.native.*` session keys for direct
optimizer installs. Backend-managed sessions freeze those native policy keys so
they cannot diverge from the shared admission ledger. The
`datafusion_nexus.request.*` namespace is intentionally request-scoped and stays
mutable on those embedded DataFusion sessions only for planner evidence. Set
`datafusion_nexus.request.graph_raw_input_edges` (edge-count evidence for graph
memory pricing when source statistics are unavailable) through SQL or
DataFusion's session-option API after Nexus registers the extension.
Caller-selected grant bytes and request-scoped grant floors are not supported.
Flight SQL does not support session-scoped `datafusion_nexus.*` keys through SQL
`SET`; configure the server ordinal profiles and queue policy instead. The server does not load
request keys from a `DATAFUSION_NEXUS_*` environment variable during startup.

## Iceberg sources and workspace overlay

The local REST catalog is the primary demo source. It exposes the five
[citation network tables](../cugraph/demo-dataset.mdx) as
`lake.citation_network.citation_edges`, `citation_edges_by_dst`, `papers`,
`paper_authors`, and `paper_fos`.

Remote Parquet objects can use the persistent lakehouse byte cache:

```bash
NEXUS_LAKEHOUSE_CACHE_ROOT=/var/cache/datafusion-nexus/lakehouse \
NEXUS_LAKEHOUSE_CACHE_READ=enabled \
NEXUS_LAKEHOUSE_CACHE_POLICY=read_through \
NEXUS_LAKEHOUSE_CACHE_MAX_BYTES=536870912000
```

`read_through` fills misses in the background; `fill_before_read` blocks until
the complete object is published locally; `disabled` never fills. This
persistent byte cache is separate from GPU device memory.

Set `NEXUS_ICEBERG_FOOTER_PRUNING=true` to enable native object-store footer
pruning. It applies safe static and dimension-derived filters to Parquet row
groups before execution; a footer-read failure skips that pruning step without
failing the query.

A mutable workspace overlay exposes those source tables under unqualified names
while keeping interactive DDL local to `datafusion.public`:

```bash
NEXUS_SERVER_WORKSPACE_CATALOG=datafusion \
NEXUS_SERVER_WORKSPACE_SCHEMA=public \
NEXUS_SERVER_WORKSPACE_BACKING_CATALOG=lake \
NEXUS_SERVER_WORKSPACE_BACKING_SCHEMA=citation_network \
NEXUS_SERVER_WORKSPACE_BACKING_ALIASES=citation_edges,citation_edges_by_dst,papers,paper_authors,paper_fos
```

With the overlay, `SELECT * FROM citation_edges LIMIT 10` resolves through to
`lake.citation_network.citation_edges`, and
`CREATE VIEW target_edges AS ...` writes to `datafusion.public`. CTAS snapshots
used by a few examples are local workspace tables for deterministic re-use; they
do not write to `lake.citation_network`. Fully-qualified names keep working too.

Keep `DATAFUSION_CATALOG_DEFAULT_CATALOG=datafusion` and
`DATAFUSION_CATALOG_DEFAULT_SCHEMA=public` when the backing Iceberg catalog is
read-only. If the default catalog/schema points directly at Iceberg, interactive
DDL is routed to that read-only source catalog and may fail.

AWS Glue uses the same catalog contract, but it requires an AWS account,
warehouse bucket, and credentials. The local REST configuration remains the
reproducible website path.

For Glue with `remote_kvikio`, keep the AWS region variables aligned:
`AWS_REGION` is consumed by the Iceberg/Glue catalog path, while KvikIO's
process-global S3 behavior expects `AWS_DEFAULT_REGION`. On private buckets,
setting only `AWS_REGION` can make the remote read path fail with unsigned S3
requests and 403 responses.

GPU Parquet execution always gives cuDF a local path, lakehouse-cache path, or
remote S3 URI. KvikIO owns the data I/O and may use native cuFile or its
compatibility implementation according to process-global
`KVIKIO_COMPAT_MODE=ON|OFF|AUTO`. Nexus does not download data objects or ranges
for the decoder and does not fall back to another Parquet data path. A missing
remote KvikIO backend or unusable source profile is a structured planning or
execution error.

`KVIKIO_COMPAT_MODE` must be fixed before the process starts. Testing multiple
modes requires independent server processes because KvikIO initialization is
process-global. Physical GDS mount prefixes are not a Nexus configuration
surface; local path eligibility and native-versus-compatibility I/O remain
KvikIO responsibilities.

A condensed Glue configuration looks like:

```bash
NEXUS_ICEBERG_CATALOG_KIND=glue \
NEXUS_ICEBERG_CATALOG_NAME=glue \
NEXUS_ICEBERG_NAMESPACE=nexus_graph \
NEXUS_ICEBERG_GLUE_CATALOG_ID=123456789012 \
NEXUS_ICEBERG_WAREHOUSE=s3://your-bucket/warehouse \
AWS_REGION=us-west-2 \
AWS_DEFAULT_REGION=us-west-2 \
NEXUS_ICEBERG_S3_REGION=us-west-2 \
NEXUS_ICEBERG_S3_CREDENTIAL_SOURCE=default_chain \
NEXUS_SERVER_CUGRAPH_ENABLED=true \
NEXUS_SERVER_BIND=127.0.0.1:50051 \
flock /tmp/cudf-gpu.lock bash scripts/dev/run_server.sh
```
