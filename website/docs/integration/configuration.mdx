# Configuration

This page is the settings reference for the Flight SQL server process, ordered
by TOML table. An embedded Rust service configures the engine through
[DataFusion Session](./datafusion-session.mdx).

| Surface              | Configure with                                  | Owns                                                                   |
|----------------------|-------------------------------------------------|------------------------------------------------------------------------|
| Flight SQL process   | `ServerConfig`, TOML, and environment variables | Listen address, admission, auth, workspace overlay, and retention      |
| Embedded GPU backend | `AlgeonGpuBackend::builder()`                   | Device ownership, capacity, queues, and execution mode                 |
| DataFusion session   | `SessionConfig`                                 | Standard DataFusion behavior (catalogs, batch size, target partitions) |

`ServerConfig::from_env()` starts from built-in defaults, overlays the TOML file
named by `ALGEON_SERVER_CONFIG_FILE`, then applies matching environment
overrides. The file accepts `[auth]`, `[admission]`, `[native]`,
`[observability]`, `[cugraph]`, `[models]` and `[s3]`; an unknown field fails
startup.

## Minimal GPU server {/* #minimal-gpu-server */}

Every selected CUDA ordinal needs a single device profile, even when all of
its values are defaults:

```toml
# server.toml
[[admission.device_profiles]]
device_ordinal = 0
```

```bash
export ALGEON_SERVER_CONFIG_FILE="$PWD/server.toml"
export ALGEON_SERVER_GPU_DEVICES=0

flock /tmp/cudf-gpu.lock bash scripts/dev/run_server.sh
```

The [device profile table](#admission) lists each default. A production
deployment sets explicit limits only where it needs them.

## Admission {/* #admission */}

| Environment variable | Default | Purpose |
|---|---|---|
| `ALGEON_SERVER_BIND` | `0.0.0.0:50051` | Flight SQL listen address |
| `ALGEON_SERVER_LOG` | `info` | Tracing filter |
| `ALGEON_SERVER_CONFIG_FILE` | unset | TOML overlay path |
| `ALGEON_SERVER_STATEMENT_TICKET_TTL_SECS` | `300` | How long an unconsumed statement ticket waits for `DoGet` |
| `ALGEON_SERVER_GPU_DEVICES` | `0` | Comma-separated CUDA ordinals |
| `ALGEON_SERVER_ADMISSION_MAX_QUEUED_ATTEMPTS` | `64` | Maximum queued admission waiters |
| `ALGEON_SERVER_ADMISSION_MAX_QUEUE_WAIT_MS` | `30000` | Maximum wait for a compatible device |

- The queue values also exist under `[admission]` as `max_queued_attempts` and
  `max_queue_wait_ms`; the environment wins.
- Admission is FIFO among capability-compatible waiters, with no overtaking or
  protected-waiter setting.
- The queue wait ends when a device grant is placed. The query's own deadline
  and cancellation bound the execution-context build after that.
- Capabilities and memory ownership are not file settings. The shipped server
  declares `WholeDeviceExclusive` ownership for every selected ordinal; custom
  embedders declare it through the Rust API.

Each `[[admission.device_profiles]]` entry takes the fields below. A rejected
value stops startup with the `invalid_configuration` error code.

| Field | Default | Constraint |
|---|---|---|
| `device_ordinal` | Required | One profile for each ordinal in `ALGEON_SERVER_GPU_DEVICES`. |
| `memory_limit_bytes` | Automatic capacity | At most the device memory Algeon owns. |
| `backend_reserve_bytes` | Unset | Required with an explicit `memory_limit_bytes`; must leave managed capacity. |
| `default_query_limit_bytes` | Derived from managed capacity | Positive and within managed capacity minus `cache_cap_bytes`. |
| `max_active_attempts` | `2` | Positive. |
| `source_work_per_attempt` | `1` | Positive. |
| `cache_cap_bytes` | `0` (no resident GPU cache) | Below managed capacity. |
| `install_telemetry` | `true` | Optional boolean. |
| `worker_count` | `max_active_attempts + 1` | At least `max_active_attempts + 1`. |
| `stream_pool_size`, `lane_count` | Engine-derived | Set together with `worker_count`, or omit all three. |

- A missing, unselected or duplicate profile ordinal is an error.
- `worker_count` counts the device's GPU execution workers. One is reserved
  for context setup and release cleanup, letting queries start and finish
  while the others execute queries.
- Automatic capacity already subtracts a driver reserve. An explicit limit
  declares its own `backend_reserve_bytes`, where `0` is a deliberate choice.
- The shipped server owns the whole device. Its `memory_limit_bytes` ceiling
  is the CUDA-visible total, below the nominal card size.
- `default_query_limit_bytes` is the immutable cap for a query whose embedding
  caller supplies none; planner estimates do not resize it.
- The startup log prints the setting, configured value, ceiling and largest
  accepted value in bytes and GiB; each of the four byte fields reports the
  largest value its capacity accepts. Lower the setting in that device's entry
  to at most that value.

<details>
<summary>Example rejection</summary>

```text
invalid server configuration: failed to initialize ownership-enforcing GPU backend core: device 0 memory_limit_bytes is 102005473280 bytes (95.00 GiB) but Algeon owns 101973819392 bytes (94.97 GiB) of device memory; the largest accepted memory_limit_bytes is 101973819392 bytes (94.97 GiB) [device_ordinal=0, configured_limit_bytes=102005473280, owned_capacity_bytes=101973819392, reason=explicit_capacity_exceeds_owned_capacity]
```

</details>

## Native execution {/* #native-execution */}

### Execution mode {/* #execution-mode */}

The default is `native_preferred`. `functions_only` keeps ordinary SQL on
DataFusion CPU and uses the GPU only for explicit cuGraph and cuVS UDTFs:

```toml
[native]
execution_mode = "functions_only"
```

```bash
export ALGEON_SERVER_EXECUTION_MODE=functions_only
```

[Choose an execution mode](./datafusion-session.mdx#choose-an-execution-mode)
describes `native_preferred`, `functions_only` and `native_required`, their
composition boundaries, host staging limits and embedded Rust configuration.
The mode is backend policy with no SQL `SET` form. Every mode still needs UDTF
features, registration, device profiles and GPU admission.

### Native settings {/* #native-settings */}

Each setting is accepted under `[native]` or through the environment, and each
can be supplied independently.

| TOML field | Environment variable | Default |
|---|---|---|
| `execution_mode` | `ALGEON_SERVER_EXECUTION_MODE` | `native_preferred` |
| `max_source_chunk_bytes` | `ALGEON_SERVER_NATIVE_MAX_SOURCE_CHUNK_BYTES` | Derived from the admitted grant |
| `max_row_groups_per_chunk` | `ALGEON_SERVER_NATIVE_MAX_ROW_GROUPS_PER_CHUNK` | `1` |
| `max_retry_attempts` | `ALGEON_SERVER_NATIVE_MAX_RETRY_ATTEMPTS` | `3` |
| `max_source_reads_in_flight` | `ALGEON_SERVER_NATIVE_MAX_SOURCE_READS_IN_FLIGHT` | `2` |
| `source_chunk_planning_mode` | `ALGEON_SERVER_NATIVE_SOURCE_CHUNK_PLANNING_MODE` | `conservative` (or `local_parquet_throughput`) |
| `statistical_aggregate_execution_mode` | `ALGEON_SERVER_NATIVE_STATISTICAL_AGGREGATE_EXECUTION_MODE` | `gpu_native_tolerant` |
| `lakehouse_footer_pruning` | `ALGEON_SERVER_NATIVE_LAKEHOUSE_FOOTER_PRUNING` | `false` |

- Device capacity comes only from [`[[admission.device_profiles]]`](#admission);
  native settings carry no device-budget planning placeholder.
- Without `max_source_chunk_bytes`, the immutable grant sizes source reads. An
  explicit value limits the source-byte grouping target.
- Compatible row-group chunks coalesce into batches. One row group per chunk
  keeps each a separate retry unit inside a coalesced read.
- Before the next read, source-adjacent aggregates account for observed
  decoded and staged bytes per row and live allocation-domain usage. The
  allocator enforces the grant, retained aggregate and graph state included.

`statistical_aggregate_execution_mode` governs `stddev` and `var`. The default
keeps them on the GPU, where floating-point bits can differ from DataFusion
and precision degrades when values are large relative to their spread.
`datafusion_exact_host_welford` matches DataFusion by copying the aggregate
input to host memory. A query is not rewritten to native execution when that
mode has no exact evaluation for its group keys or the other aggregates in the
same `GROUP BY`.

The former `final_plan_requirement` field is gone, and startup fails when
`ALGEON_SERVER_FINAL_PLAN_REQUIREMENT` is set.

## Authentication {/* #authentication */}

Authentication is TOML-only and defaults to `disabled`. Use that default only
on a trusted local network. Static Basic credentials can be exchanged for
server-issued bearer tokens:

```toml
[auth.mode]
kind = "basic_bearer"
token_ttl_secs = 3600

[[auth.mode.users]]
username = "alice"
password_hash = "$argon2id$v=19$m=19456,t=2,p=1$..."
```

`token_ttl_secs` is required and positive; non-expiring bearer tokens are
unsupported. `password_hash` must be a valid Argon2 PHC string, plaintext is rejected, and
usernames must be unique.

## Runtime observation retention {/* #runtime-observation-retention */}

The defaults retain bounded query records and sealed reports; change them only
when traffic or exporter behavior needs another budget. A data statement's
runtime observation belongs to its execution attempt. A metadata statement, such as a catalog query, runs no native work;
its runtime artifact is the control frame, and its query stats come from the
server's own capture.

| TOML field under `[observability]` | Environment override | Default |
|---|---|---|
| `per_query_max_records` | `ALGEON_SERVER_OBSERVABILITY_PER_QUERY_MAX_RECORDS` | `65536` |
| `per_query_max_bytes` | `ALGEON_SERVER_OBSERVABILITY_PER_QUERY_MAX_BYTES` | 8 MiB |
| `active_logical_capture_max_bytes` | `ALGEON_SERVER_OBSERVABILITY_ACTIVE_LOGICAL_CAPTURE_MAX_BYTES` | Admission requirement plus 1 GiB |
| `global_sealed_max_count` | `ALGEON_SERVER_OBSERVABILITY_GLOBAL_SEALED_MAX_COUNT` | `1024` |
| `global_sealed_max_bytes` | `ALGEON_SERVER_OBSERVABILITY_GLOBAL_SEALED_MAX_BYTES` | 1 GiB |
| `sealed_ttl_secs` | `ALGEON_SERVER_OBSERVABILITY_SEALED_TTL_SECS` | `3600` |
| `shutdown_grace_secs` | `ALGEON_SERVER_OBSERVABILITY_SHUTDOWN_GRACE_SECS` | `30` |

All values must be positive. The capture budget never refuses a query; one
that does not fit runs without capture, its SQL text is not kept, and its query
stats report `unavailable_reason=active_capture_budget` during and after the
run. Admission alone decides overload.

<details>
<summary>How the capture budget is computed</summary>

Each live Flight SQL query reserves logical capture bytes until it finishes:
three times `per_query_max_bytes` plus its sealed artifact (twice
`per_query_max_bytes`, capped at `global_sealed_max_bytes`), 40 MiB with the
defaults. It holds the reservation while planning and finalizing, outside its
admission slot.

Unset, the budget is the capture of every attempt admission can hold at once
(each profile's `max_active_attempts` plus `admission.max_queued_attempts`)
plus 1 GiB. The server logs the budget and that requirement at startup.

Reservations follow registration order. Statements that plan, finalize or never
take an admission slot also hold them, and a query within the admission bounds
can still run without capture.

</details>

The server registers at most 1024 live Flight SQL statements, counting every
statement that is planning, ticketed but unread, executing (CPU-only and
metadata included) or finalizing. Startup and `FlightSqlServerBuilder::build`
fail with `admission_exceeds_live_query_capacity` when the admission bounds
alone hold 1024 attempts or more. Its `config_field` is
`ALGEON_SERVER_ADMISSION_MAX_QUEUED_ATTEMPTS`, or
`admission.device_profiles.max_active_attempts` when the profiles fill the cap
alone. Because statements outside admission share the cap, registration can
refuse one while admission has room.

## GPU SQL UDTFs {/* #gpu-sql-udtfs */}

```toml
[cugraph]
max_input_staging_bytes = 8589934592
max_output_staging_bytes = 2147483648
```

| Setting | Default | Meaning |
|---|---|---|
| `ALGEON_SERVER_CUGRAPH_ENABLED` | `true` | Registers the `cugraph_*` SQL frontend. |
| `ALGEON_SERVER_CUGRAPH_CONSTRUCTION_POLICY` | `python_cugraph` | `python_cugraph` or `raw_libcugraph`. |
| `cugraph.max_input_staging_bytes` | 1 GiB | Retained Arrow batches from edges and graph side inputs, counted together. |
| `cugraph.max_output_staging_bytes` | 1 GiB | Eagerly materialized Arrow results. |

- With `ALGEON_SERVER_CUGRAPH_ENABLED=false`, the policy variable or either
  staging field fails startup. Staging values must be positive.
- A binary without the `cugraph` feature can expose the frontend, but
  execution returns a structured `required_feature_disabled` error.
- Per-call graph values, such as a named `construction_policy`, override these
  defaults ([Graph Inputs and Construction](../cugraph/graph-options.mdx)).
- Input buffers shared by slices or by different source partitions count once
  across retained batches. GPU-resident inputs bypass host input staging.
- Staging limits apply to host RAM apart from the device grant, and the
  DataFusion memory pool may impose a lower limit.
- Embedded sessions pass `GpuIslandHostBoundaryConfig` through
  `CugraphSqlConfig.host_boundary_config`; conflicting reinstallations fail.

cuVS SQL has no enable variable and is installed on every session. The `cuvs`
feature decides whether its UDTFs execute or return
`required_feature_disabled` ([cuVS execution](../cuvs/overview.mdx#execution)).

### Models and forest inference {/* #models-and-forest-inference */}

```toml
[models]
root = "/srv/models"
max_model_bytes = 268435456
```

| `[models]` field | Default | Constraint |
|---|---|---|
| `root` | unset | Enables `cuml_forest_predict`; must be an existing directory at startup. |
| `max_model_bytes` | 256 MiB | Positive, and only valid with `root`. |

Without a `[models]` table, `gpu_list_functions()` lists `cuml_forest_predict` as
unavailable with `model_root_unconfigured`. Neither field has an environment
override; embedded sessions use `CumlModelStoreConfig` through
`try_with_cuml_sql_config`, and [Model files](../cuml/udtfs/cuml_forest_predict.mdx#model-files)
covers path resolution, rejections and the trust boundary.

## S3 and Parquet sources {/* #s3-storage */}

`[s3]` configures the storage behind every `s3://` Parquet source. DataFusion
scans, footer pruning and native GPU reads all use it. A DataFusion fallback
therefore reads the same endpoint, region and credentials as GPU execution.

| TOML field | Environment variable | Meaning |
|---|---|---|
| `endpoint` | `ALGEON_SERVER_S3_ENDPOINT` | S3-compatible endpoint, such as `http://localhost:9000` |
| `region` | `ALGEON_SERVER_S3_REGION` | Region of every bucket |
| `path_style` | `ALGEON_SERVER_S3_PATH_STYLE` | `true` for path-style addressing (MinIO, RustFS) |
| `unsigned` | `ALGEON_SERVER_S3_UNSIGNED` | `true` for anonymous requests |

The table or any variable enables the storage, and variables override fields.
Credentials come from the default AWS chain (`AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`) unless `unsigned` is set. Without the table, no
`s3://` object store is registered for DataFusion and native reads use the
process-wide AWS settings.

### Parquet source flags {/* #parquet-source-flags */}

Native scans read local and `s3://` Parquet. Without `[s3]`, KvikIO reads
`AWS_DEFAULT_REGION` while engine metadata reads prefer `AWS_REGION`; set both
to one region. `KVIKIO_COMPAT_MODE=ON|OFF|AUTO` belongs in the process
environment before startup, outside `ServerConfig`.
`native.lakehouse_footer_pruning = true` enables footer row-group pruning for
`s3://` scans ([Projection and scan pruning](../design/data-path.mdx#projection-and-scan-pruning)).

## Workspace overlay {/* #workspace-overlay */}

A workspace overlay keeps interactive DDL local and reads through to a backing
schema:

```bash
export ALGEON_SERVER_WORKSPACE_CATALOG=<workspace catalog>
export ALGEON_SERVER_WORKSPACE_SCHEMA=<workspace schema>
export ALGEON_SERVER_WORKSPACE_BACKING_CATALOG=<backing catalog>
export ALGEON_SERVER_WORKSPACE_BACKING_SCHEMA=<backing schema>
export ALGEON_SERVER_WORKSPACE_BACKING_ALIASES=<table>,<table>
```

The backing catalog and schema are set together and must already be registered
in the server session, or session construction fails with a configuration
error. The standalone server registers no catalog beyond DataFusion's default.
The workspace pair defaults to `datafusion.public` and must differ from the
backing pair. Without aliases, every backing table is exposed.

## DataFusion session configuration {/* #datafusion-session-configuration */}

The server reads `SessionConfig::from_env()`, with keys such as
`DATAFUSION_EXECUTION_BATCH_SIZE`, `DATAFUSION_EXECUTION_TARGET_PARTITIONS`,
`DATAFUSION_CATALOG_DEFAULT_CATALOG` and `DATAFUSION_CATALOG_DEFAULT_SCHEMA`.
In `native_preferred` and `native_required`, the native optimizer overrides
one DataFusion optimizer default, described in
[Uncorrelated scalar subqueries](../design/native-lowering.mdx#uncorrelated-scalar-subqueries).

Native execution policy lives only in `[native]`, the `ALGEON_SERVER_NATIVE_*`
variables or the embedded `AlgeonGpuBackendBuilder`. Algeon registers no
session configuration extensions, sessions carry standard DataFusion
configuration only, and `SET algeon_datafusion.*` fails with an unrecognized
configuration key error.

## Removed Iceberg settings {/* #removed-iceberg-settings */}

Startup fails when any variable below has a non-blank value; the error names
the variable and says it belonged to the removed Iceberg integration. Remove
them from the deployment environment.

<details>
<summary>Removed variables</summary>

- `ALGEON_ICEBERG_CATALOG_KIND`, `ALGEON_ICEBERG_CATALOG_NAME`,
  `ALGEON_ICEBERG_NAMESPACE`, `ALGEON_ICEBERG_TABLES`,
  `ALGEON_ICEBERG_WAREHOUSE`, `ALGEON_ICEBERG_SCAN_PLANNING_TIMEOUT_SECS`
- `ALGEON_ICEBERG_GLUE_CATALOG_NAME`, `ALGEON_ICEBERG_GLUE_CATALOG_ID`,
  `ALGEON_ICEBERG_GLUE_URI`, `ALGEON_ICEBERG_REST_URI`,
  `ALGEON_ICEBERG_REST_PREFIX`, `ALGEON_ICEBERG_REST_TOKEN`,
  `ALGEON_ICEBERG_REST_CATALOG_HANDLE`
- `ALGEON_ICEBERG_S3_ENDPOINT`, `ALGEON_ICEBERG_S3_REGION`,
  `ALGEON_ICEBERG_S3_PATH_STYLE`, `ALGEON_ICEBERG_S3_CREDENTIAL_SOURCE`
- `ALGEON_ICEBERG_FOOTER_PRUNING`
- `ALGEON_LAKEHOUSE_CACHE_ROOT`, `ALGEON_LAKEHOUSE_CACHE_READ`,
  `ALGEON_LAKEHOUSE_CACHE_POLICY`, `ALGEON_LAKEHOUSE_CACHE_MAX_BYTES`

</details>

[`[s3]`](#s3-storage) replaces the Iceberg S3 group and
`native.lakehouse_footer_pruning` replaces footer pruning. The cache group has
no replacement, so a server process cannot enable the persistent lakehouse byte
cache for `s3://` Parquet. [Iceberg support](./overview.mdx#iceberg-support)
gives the status of Iceberg sources.
