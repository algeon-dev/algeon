# Integrating Nexus

DataFusion Nexus fits behind ordinary DataFusion APIs. Choose the integration
surface that matches the service boundary you own:

| Surface | Use it when | Start here |
| --- | --- | --- |
| DataFusion session | You already own a Rust backend, DataFusion session lifecycle, auth, tenancy, and result formatting. | [DataFusion Session](./datafusion-session.mdx) |
| Embedded backend example | You want one Rust process with product-owned REST workflows and an ad-hoc Flight SQL side door sharing one GPU-native admission ledger. | [Embedded Backend Example](./embedded-backend-example.mdx) |
| Flight SQL server | You want a remote Arrow Flight SQL endpoint for non-Rust clients, notebooks, agents, or service-to-service calls. | [Flight SQL server](./flight-sql-server.mdx) |

All three surfaces execute supported relational plans on cuDF. The `cugraph`
and `cuvs` features add SQL-visible `cugraph_*` and `cuvs_*` table functions;
the `iceberg` feature adds Iceberg/Glue/REST/S3 source integration. cuVS has
no lower-level bounded peak-memory preflight yet, so its execution currently
fails closed with structured `unsupported_operator`.

## Common flow

1. Build the stack with the features your deployment needs. The full source
   build is covered in [Build & Test](../build/overview.md).
2. Pick an integration surface: a DataFusion session, the embedded dual-frontend
   example, or the Flight SQL server.
3. Size GPU memory and configure table sources before running user queries. The
   environment-variable contract is in [Configuration](./configuration.mdx).
4. If you use GPU SQL, follow
   [Discover & Validate GPU Functions](../guides/gpu-function-discovery.mdx)
   to list, describe, and validate available calls; filter the inventory by
   `provider` when needed. The
   [GPU Function Catalog API](../reference/gpu-function-catalog.mdx) defines
   the exact metadata and validation schemas.
5. Before shipping a query, check whether its planned path stays on the GPU —
   and why not, if it doesn't — with
   [GPU coverage validation](./gpu-coverage-validation.mdx)
   (`nexus_explain_coverage` in embedded SQL, `EXPLAIN GPU` through Flight SQL,
   and `validate_query` in Rust).
6. At your application boundary, enrich errors that carry a typed Nexus source,
   then keep your existing policy for ordinary DataFusion failures. See
   [Handling Errors](./handling-errors.mdx).

The [cuGraph SQL API](../cugraph/overview.mdx) and
[cuVS SQL API](../cuvs/overview.mdx) sections are the function-level
contracts. They share discovery and validation while documenting their distinct
relation syntax, input semantics, lifecycle, and execution constraints.
