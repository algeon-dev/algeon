# Graph, vector search, and model scoring in one SQL query <span className="heading-subtitle">A MerRec case study over 1.27 billion marketplace events</span> {/* #merrec */}

[MerRec](https://huggingface.co/datasets/mercari-us/merrec) contains 1.27 billion
events from 5.57 million Mercari US shoppers between May and October 2023:
views, likes, cart taps, offers and completed purchases across 82.6 million
listings.

Every query here went over Arrow Flight SQL to one Algeon server with an
NVIDIA RTX PRO 6000 (96 GB) and read Parquet files from local NVMe. A 90 GiB
grant capped each query's device allocations. The shopper taste vectors
(`mr_taste64`) and the XGBoost model (`propensity_xgb.json`) were prepared
before the queries ran. In a deployment, the application chooses seeds,
cohorts and parameters and passes the selected shoppers on to its campaign
service.

## Data scope

The source contains 1,268,092,738 events, 82,614,392 items and 5,566,055 users.
`merrec_events` retains events; `merrec_items` keeps the latest attributes for
each item. `mr_taste64`, read by the campaign and lookalike queries, is a
prepared table of 64 category-share features per shopper, built by one SQL
statement over the same events. Its SQL is on the
[approximate search page](../../cuvs/udtfs/cuvs_cagra.mdx?dataset=merrec#examples).

A fan is a distinct user with an `item_like` event for a brand. A purchase is a
`buy_comp` event. Repeated views count toward behavioral features. Each query
states its time window and eligible audience. Quoted timings include planning,
execution and result receipt. Item names, categories and prices are the latest
retained values, not attributes reconstructed at event time.

Each section links to its saved SQL and results, with server configurations and
execution metrics. Each query ran four times, and the quoted timing is the median
of runs 2 to 4 with the source pages resident in the OS page cache. Detailed
reproduction steps and scripts are documented in the
[scale README](https://github.com/algeon-dev/algeon/blob/main/fixture/demo/merrec/scripts/scale/README.md).
Each query uses one GPU and its working set must fit the configured memory limit.
The largest allocator peak among these queries was 75.1 GiB of a 90 GiB grant,
in the duplicate-brand query.
