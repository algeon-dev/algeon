# MerRec Marketplace

[MerRec](https://huggingface.co/datasets/mercari-us/merrec) records browsing
and purchase events from the Mercari US marketplace. The demo uses all six
source months. SQL filters and aggregates interaction events into graph inputs;
cuGraph results can feed further filters, joins, and aggregates in the same
statement. The item-user PageRank query below filters view events, counts
repeated interactions as edge weights, and returns the highest-ranked items.
Twelve full-scale examples on the algorithm pages start from the same raw
tables and cover 17 cuGraph, cuVS, and cuML functions.

## At a glance

| Item | Details |
|---|---|
| Source | [mercari-us/merrec](https://huggingface.co/datasets/mercari-us/merrec), May through October 2023, pinned to `dd2b3c6f6f19d4814bb839ee6e8ab41926a14343` |
| Scale | 1,268,092,738 events, 82,614,392 items, and 5,566,055 users |
| Files | 2,170 source shards, 166.08 GB compressed; normalized events and items total 90.33 GB |
| Preparation | The fixture retains all source events and stores the latest attributes once per item |
| Python packages | `pyarrow`, and the `duckdb` CLI on `PATH` for conversion |
| Server | `127.0.0.1:50064`; the scale configuration allows a 90 GiB query on a 94 GiB device ledger |
| Queries | Category engagement, user activity, item-user PageRank, batched vector search, and the full-scale algorithm examples listed below |

## Prepare the data

Run commands from the repository root. The
[fixture README](https://github.com/algeon-dev/algeon/blob/main/fixture/demo/merrec/README.md)
documents acquisition, conversion, and source columns. Download and convert
all six months on NVMe:

```bash
MERREC_ROOT=/mnt/algeon-nvme/algeon/fixture/demo/merrec
fixture/fixture.sh merrec prepare --partition all --download --download-workers 32 \
  --out-dir "$MERREC_ROOT" --duckdb-memory-limit 32GB --duckdb-threads 8 --force
```

The converter requires every shard in the selected scope. The 32GB setting
controls DuckDB host memory during conversion. GPU query capacity is configured
separately. Stop the server before replacing its registered data files.

## Start the server

```bash
cargo build --workspace --all-features --release --bin algeon_server

ALGEON_SERVER_CONFIG_FILE="$PWD/fixture/demo/merrec/scripts/scale/server.toml" \
ALGEON_SERVER_BIND=127.0.0.1:50064 \
flock -x /tmp/cudf-gpu.lock target/release/algeon_server
```

The scale configuration targets the development host's 96 GB GPU: a 94 GiB
device ledger, 1 GiB backend reserve, 90 GiB query limit, and one active
attempt. Set limits appropriate to the available device capacity on other
hosts. `native_required` rejects remaining DataFusion CPU operators, including
relational operators around explicit GPU functions. The configuration's
`[models]` root, `fixture/demo/merrec/models`, holds the XGBoost model that
the forest-predict example scores.

## Register the tables

From another terminal, register the complete source tables:

```bash
MERREC_ROOT=/mnt/algeon-nvme/algeon/fixture/demo/merrec
MERREC_REPORT="$PWD/target/merrec-scale/full/gpu"
MERREC_RESULTS="$MERREC_ROOT/scale-results/gpu"

python3 scripts/dev/merrec_run.py --uri grpc://127.0.0.1:50064 --register \
  --data-dir "$MERREC_ROOT/parquet" \
  --report-dir "$MERREC_REPORT" --results-dir "$MERREC_RESULTS"
```

The runner checks registered table locations before recording the input
manifest. Start a fresh server when changing dataset scope. The graph input is
computed within the PageRank statement; it requires no saved graph snapshot.

## Run the examples

```bash
python3 scripts/dev/merrec_run.py --uri grpc://127.0.0.1:50064 \
  --report-dir "$MERREC_REPORT" --results-dir "$MERREC_RESULTS" \
  --timeout 1800 --repeats 5 \
  fixture/demo/merrec/scripts/scale/01_category_engagement.sql \
  fixture/demo/merrec/scripts/scale/02_user_activity.sql \
  fixture/demo/merrec/scripts/scale/04_item_pagerank.sql
```

Each report retains complete output, Flight elapsed time, query statistics,
and `EXPLAIN GPU` coverage. PageRank elapsed time includes edge preparation,
graph construction, the algorithm, and result receipt. The
[scale workflow](https://github.com/algeon-dev/algeon/blob/main/fixture/demo/merrec/scripts/scale/README.md)
records CPU comparisons and vector preparation. Graph size is measured after
edge aggregation and normalization; the source event count is a separate value.

The full-scale algorithm examples need the prepared `mr_taste64` table and,
for forest predict, a trained model. `--prepare-scale` builds and registers
the taste tables; the
[scale workflow](https://github.com/algeon-dev/algeon/blob/main/fixture/demo/merrec/scripts/scale/README.md#full-scale-exploration-demos)
lists every example file and the full command sequence:

```bash
S=fixture/demo/merrec/scripts/scale
python3 scripts/dev/merrec_run.py --uri grpc://127.0.0.1:50064 --prepare-scale \
  --data-dir "$MERREC_ROOT/parquet" \
  --report-dir "$MERREC_REPORT" --results-dir "$MERREC_RESULTS" \
  --timeout 1800 $S/26_propensity_training_features.sql
python3 $S/train_propensity_model.py \
  "$MERREC_RESULTS/26_propensity_training_features.parquet" \
  fixture/demo/merrec/models/propensity_xgb.json
python3 scripts/dev/merrec_run.py --uri grpc://127.0.0.1:50064 \
  --report-dir "$MERREC_REPORT" --results-dir "$MERREC_RESULTS" \
  --timeout 1800 --repeats 3 $S/07_brand_overlap.sql $S/10_barbie_tie_ins.sql
```

The complete six-month PageRank query has been validated with 87,055,073
vertices and 1,682,503,472 normalized directed edges representing the undirected
graph. It completed within the 90 GiB query limit, with a measured allocator
peak of 89.07 GiB, zero host boundaries, and zero retries. The statement uses
all six months without an additional time or cohort filter. Five runs completed;
the median Flight latency excluding the first run was 19.31 seconds on the
96 GB development GPU with cached source files.

### Browsing graph

The source views in
[`sql/01_graph_views.sql`](https://github.com/algeon-dev/algeon/blob/main/docs/research/merrec/sql/01_graph_views.sql)
pair adjacent `item_view` events within `(user_id, session_id)`, ordered by
`(event_time, event_id)`. A pair becomes a transition when it crosses
different `product_id` values with a positive time gap of at most 30 minutes.
Both endpoint markets need at least 10 distinct viewers, and each retained
directed edge needs support from at least three distinct users. Its weight
counts those users.

The saved graph has 1,711 market vertices and 4,963 directed transition
edges. The audience graph has 59,629 distinct market-user edges from
`item_view` events. The snapshot inputs and registration SQL are
[`sql/02_graph_snapshots.sql`](https://github.com/algeon-dev/algeon/blob/main/docs/research/merrec/sql/02_graph_snapshots.sql)
and
[`sql/03_register_graph.sql`](https://github.com/algeon-dev/algeon/blob/main/docs/research/merrec/sql/03_register_graph.sql).

Vertex numbers belong to the saved snapshot and can change when the graph is
rebuilt. In the captured snapshot, vertex `672` maps to product group
`15928_1315` (Nintendo, Electronics, Games).

### Audience features

[`prepare_tastes.sql`](https://github.com/algeon-dev/algeon/blob/main/docs/research/merrec/sql/prepare_tastes.sql)
keeps 1,919 users with at least 20 `item_view` events before the exclusive
cutoff of October 21, 2023. The 17 features are square roots of each user's
category shares of view events, and repeated views count separately. KMeans,
HDBSCAN, and UMAP read the same ordered features, with a separate fit in each
query.

### Sample tables

| Table | Rows | Contents |
|---|---:|---|
| `merrec_events` | 494,357 | `event_time`, `user_id`, `item_id`, `session_id`, `event_type` |
| `merrec_items` | 358,893 | `item_id`, `product_id`, name, price, three category levels, `brand_id` |
| `mr_nodes` | 1,711 | Market vertices: `product_id`, brand, category, item count, mean price, viewers |
| `mr_edges` | 4,963 | Directed browsing transitions `src`, `dst`, `weight` |
| `mr_undirected` | 3,317 | Transitions merged into undirected weighted edges |
| `mr_audience` | 59,629 | Market-user edges from `item_view` events |
| `mr_tastes` | 1,919 | Per-user view counts and the 17 category features |

The runner also defines views such as `merrec_transitions` and
`merrec_markets` over the source tables. Those views feed the snapshots above.

### Recorded results

The [discovery capture](/data/merrec-graph-capture.json) records the executed
SQL, output schema, query ID, all ten result rows, and one elapsed time of
0.13337774 seconds. That value is one Flight elapsed observation, including
planning and receipt of the complete result. Graph preparation ran before the
call on a server that had already run many queries, and no repeated
performance claim follows from it. The source shard includes 238 `buy_comp`
events.

The graph validation compares the saved personalized PageRank scores with
NetworkX. The top-15 order matches, with a maximum absolute error of
9.59610868e-7 across shared vertices against a tolerance of 1e-5. The source
snapshot comparison matched the saved nodes, transitions, edges, and audience
rows in
[`graph_validation.json`](https://github.com/algeon-dev/algeon/blob/main/docs/research/merrec/graph_validation.json).

The audience map combines saved UMAP display coordinates with HDBSCAN labels
fitted in the original 17 dimensions. Its filters keep all 1,316 noise rows
available. The campaign-theme query fits eight KMeans groups, joins their
assignments to source shares, averages those shares with equal weight for each
user, and applies Top-K to the category means.

The collection statement runs natively: its captured plan has three native
fragments and zero host DataFusion boundaries. The campaign-theme
statement has five native fragments and zero host boundaries. Their timing
observations exclude source preparation and provide no controlled performance
comparison.
