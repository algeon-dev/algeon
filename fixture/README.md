# Fixtures

## `fixture/data/` — per-host benchmark data root

`fixture/data/` is the in-repo root for benchmark/workload Parquet fixtures
(TPC-H, TPC-DS, ClickBench, SNAP graphs). Its contents are **gitignored** — they
are per-host local setup, never committed. Every script, Python tool, and doc in
this repo refers to fixtures through `./fixture/data/*`, so this directory is the
single indirection point you configure per machine.

### Expected layout

```
fixture/data/
  tpch/sf<N>/parquet/           # raw: one file per table
  tpch/sf<N>_optimized/parquet/ # lineitem split into l_orderkey-ordered shards
  tpcds/sf<N>/parquet/          # raw: one file per table, generation order
  tpcds/sf<N>_optimized/parquet/# fact tables date-clustered by *_date_sk
  clickbench/hits.parquet       # single-file layout
  clickbench/partitioned/       # hits_0.parquet … hits_99.parquet
  snap/<dataset>/parquet/       # generated by fixture/scripts/graph/snap_ingest.py
```

### Generating TPC-H / TPC-DS

`fixture/scripts/gen_tpch.py` and `gen_tpcds.py` own the full lifecycle —
generation *and* layout optimization — for each dataset. Both take one or more
scales and a `--variant` (`raw`, `optimized`, or `both`):

```bash
# Raw + optimized at SF1/10/100, onto the NVMe mount the bench harness reads:
fixture/scripts/gen_tpch.py  --scale 1 10 100 --variant both --out-root /opt/dlami/nvme/tpch
fixture/scripts/gen_tpcds.py --scale 1 10 100 --variant both --out-root /opt/dlami/nvme/tpcds

# Equivalent via the fixture.sh router (thin pass-through):
fixture/scripts/fixture.sh tpch generate  --scale 10 --variant optimized --out-root ./fixture/data/tpch
```

`gen_tpch.py` drives `tpchgen-cli`; `gen_tpcds.py` drives DuckDB's in-process
`dsdgen` (run once per scale, both layouts exported from the same in-DB tables).
Each verifies row counts after writing and `gen_tpcds.py` additionally checks that
the optimized fact tables are actually date-clustered. Run either with `--help`
for the full flag set (compression, row-group size, threads, lineitem shard
count, …).

### Setting it up on a new host / for a new developer

Point each entry at wherever your fast local storage lives — a symlink is the
usual choice, but a real directory or a download target works too:

```bash
# Host with the AWS DLAMI NVMe drive staged at boot:
ln -s /opt/dlami/nvme/tpch       fixture/data/tpch
ln -s /opt/dlami/nvme/tpcds      fixture/data/tpcds
ln -s /opt/dlami/nvme/clickbench fixture/data/clickbench
ln -s /opt/dlami/nvme/snap       fixture/data/snap

# Host with data elsewhere — repoint the symlink, no code change needed:
ln -s /mnt/fastdisk/tpch fixture/data/tpch

# Or just fetch/generate directly into the directory:
fixture/scripts/workloads/clickbench/fetch.sh --layout both --out ./fixture/data/clickbench
```

### How the Rust bench harness resolves data (read before changing the defaults)

The Rust workload harness does **not** simply read `./fixture/data/*`. It keeps a
deliberate dual path (`crates/datafusion-nexus-bench/src/workload/*/dataset.rs`):

- When the physical NVMe mount `/opt/dlami/nvme` is present
  (`default_nvme_mount_present()`), it reads from the `DEFAULT_NVME_*` paths
  **directly**. This is required for GPUDirect-Storage (GDS) direct-device reads:
  `io_capability.rs` decides GDS eligibility by prefix-matching the source path
  against the physical mount root `DEFAULT_GDS_LOCAL_MOUNT_ROOT` (`/opt/dlami/nvme`).
- Otherwise it falls back to the in-repo `DEFAULT_LOCAL_* = ./fixture/data/*` roots.

On the DLAMI host the `fixture/data/*` symlinks above point at the same bytes, so
script-side (`./fixture/data/*`) and engine-side (`/opt/dlami/nvme/*`) access stay
consistent. **Do not** rewrite the `DEFAULT_NVME_*` data constants to
`./fixture/data` to "clean up" the literal: a relative, symlink-aliased path no
longer prefix-matches the GDS mount root and would silently disable direct-device
reads on the benchmark host. "Where is my data" (fixture discovery, host-agnostic)
and "is this path on a GDS-capable device" (physical classification) are separate
axes and are meant to stay separate.
